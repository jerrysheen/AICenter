# 内容分流与硬件报价 V1

2026-10-05 用户授权：TrendForce 保留为来源，取消独立内容栏目。洞察、价格预测与供需分析进入媒体科技产业；会员目录为报告简介，完整度独立记录。实际报价进入全球行情的 AI硬件价格，存储卡归其他存储参考。

采集继续由原订阅同步与显式 feed.trendforce.sync 调用同一用例；媒体同步不再次请求 TrendForce。Connector 一次获取返回文章与原始表格，Feed Service 通过注入的分流 Port 调用 Media Service 与 HardwarePrice Service。失败后的重试按存储幂等，不另建采集 Runtime。Web 只读存储、入队既有任务。

报价归现有行情边界，使用独立 Contract、Service 和 Repository，不复用证券、股票 OHLC 或前收盘口径。前向迁移新增来源快照、报价版本和快照行引用。原始表格保存到 Instance blobs，数据库只存相对路径；未知币种、单位、有效期为 null，待核验记录不能计算涨跌。来源更新时间与采集时间分开。

序列身份包含来源、完整规格、报价类型、币种、单位、税口径与均价定义。同一报价期与完整数值相同不增加版本；新期新增观测，同期修订追加版本，旧版不可覆盖。A→B→A 是两次修订，不按全历史值哈希删掉回改。不同已知报价期最新版本形成报价历史，未核验单位仍可看已保存的原始值但不计算可比涨跌；只有一个报价期或缺报价期显示暂无历史。涨跌只比较同口径已核验观测，不把原站未明确口径的百分数当可比变化。

兼容：旧 Capture/ContentItem、状态、Tag、引用和链接保留，媒体通过身份关系读取旧状态和标签。旧 price:dram / price:flash 映射到整张快照及全部规格，不跳任意单规格。旧 Markdown 只能作为 legacy-text 快照，缺字段待核验，不伪称原始 HTML，不补造旧历史。迁移由显式已注册 Worker 用例执行，重复运行幂等，不在启动时隐式导入用户数据。日报读取真实完整度，已分流条目不重复读入 Feed；历史冻结日报不改写。

来源筛选在分页和计数前执行；请求、缓存键、返回校验都包含 sourceKey。科技产业提供全部内容视图可读报告简介，仍保留全文视图。股票行情继续原逻辑。

## 实现与迁移

### 2026-10-05 行情呈现纠正

用户明确要求与其他行情一致：AI硬件是全球行情内的资产分类，主列表复用名称／走势／价格涨跌的行布局，不另设入口或卡片目录。完整规格区分现货、合约、零售价；其他存储参考单独筛选。已保存且口径完整的报价进入“全部”，缺币种、单位等记录在硬件分类的“待核验”筛选中查看，避免默认混排。旧硬件目录深链接兼容到该分类，旧价表仍打开整表快照。

行情列表使用真实报价期的均价序列，详情绘制带日期轴、数值刻度及点位读取的价格折线；高低均价只作为报价指标，绝不构造股票 OHLC。只有一个报价期仍显示当前报价与暂无历史；缺报价期不能拿采集时间补成走势。单期记录与待核验记录不会显示虚构涨跌。列表响应的 `rawCells` 为空，原单元格留在系列明细。不带分类、以及 `dram` / `nand` / `ssd` / `other-storage` 四个分类的 `GET /api/v1/hardware-prices` 只写出 Worker 每分钟写入、并由 Web 的工作线程预先 gzip 的缓冲区；请求里不再读快照正文，也不再序列化。还没有缓冲区时返回 `pending: true`。带 `snapshotId` 的查询在 Web 的工作线程里按快照过滤、序列化并 gzip，请求等待缓冲区后写出。系列明细仍按键读取。

修复日／盘高低点表头识别，避免价格成为规格身份。对已保存原始 HTML 通过显式注册的重解析任务生成新解析版本，保留旧快照与观测；正常列表优先完整规格及新解析版本，旧链接不变。重解析只读取已保存快照，不重复抓取或增加频率。

新增 migration 40，旧 migration 不改写。`hardware-prices.js` 同时校验采集输入与页面输出；原始行包含表序号、行序号、单元格以及高低均价的原站列名。SSD 零售价身份保留品牌、接口、系列、容量的全部列，不能只按品牌去重。公开页面未明示币种和单位时仍为空；不从供应商惯例或 JavaScript 中的其他业务数据推定。

相同值可关联多个原始表格快照，列表与详情采用最新引用及源站时间；观测本身保持不可变。不同数字修订保存 previousId，重采同一原始内容不增加快照。晚到的旧源站版本不会替换较新报价。分页前排除已分流旧 ContentItem，避免日报提前停止或重复收录。

迁移命令：`node scripts/migrate-trendforce-content.mjs` 默认只读；`--run` 先在线备份，再用注册的 `feed.trendforce.migrate` handler 执行，只领取该任务，不恢复/终止其他 Worker Job。迁移复制原有准入决定和标签到媒体身份，不重新调用模型、不放宽现行入选规则。旧未记录提取证据的文章标部分正文；报告简介始终 summary_only。已验证全文后续不降级，普通媒体补全文任务跳过 TrendForce 抓取，翻译和 Tag 仍由既有 media.index.enrich 执行。

新增未验证洞察可以由原采集任务补正文，已经验证的洞察沿用排除 ID；文章订阅频率仍为原 120 分钟。并发的同一请求合并，Worker 内的分流写入串行。公开 Source 只读存储，内部 collection Source 不在 HTTP 目录和详情暴露。

### 2026-10-12 现货解析、抓取时刻与币种

生产订阅约每 30 分钟抓一次公开价表。NAND 公开页 `flash_spot` 的 Last Update 与 schema.org `dateModified` 停在 2026-09-28 14:40（GMT+8）；同日 DRAM `dram_spot` 已到 2026-10-12。公开 HTML 里没有更晚的 NAND 报价日。`/pricedetail/` 与 DRAMeXchange 价格页会转到登录，不能从会员通知补数字。

表头已变成「日高点、日低点、盘高点、盘低点、盘平均、盘涨跌幅」，标题只剩「(未税)」。旧解析把日高／日低算进规格，序列身份跟着价格分叉，最后一条干净序列停在 09-28。盘均价又和日高点混在同一行。解析器 `trendforce-tables-3` 把全部价格列排除出规格，均价／高低优先盘列。

币种规则收窄：DRAM／NAND 的现货与合约标题含「未税」，且不是 Wafer、Module、eMMC、Card、SSD、Street 时，记 `USD` / `chip`。SSD、晶圆、eMMC、存储卡、街价仍只在页面写明币种时填写。已有序列若规格、分类、报价类型相同，且币种或单位有一侧为空，沿用观测最多的那条，避免表头改名后另开历史。

每次抓取都写 `last_checked_at`。页面级 `hardware_price_page_checks.last_changed_at` 只在内容哈希变化时前移；同一哈希且同一解析版本只更新检查时间，不新增观测。仅解析版本变化会新快照，但不把页面标成内容已变。migration 54 只加列和检查表，并按已有快照回填。

报价另有注册任务 `feed.trendforce.prices`。Worker 用两条 `daily` 日程，默认 Asia/Shanghai 10:30 与 17:30，最多四档。`AI_CENTER_TRENDFORCE_PRICE_SYNC=0` 关闭；`AI_CENTER_TRENDFORCE_PRICE_AT` 为逗号分隔的 `HH:MM`；`AI_CENTER_TRENDFORCE_PRICE_TIMEZONE` 默认 `Asia/Shanghai`。原订阅同步仍走同一解析与仓储。`config/media.json` 的 TrendForce 文章源保持关闭。行情行显示币种／单位，以及「已抓取、页面未变」或「抓到新内容」。生效需要重启 Worker；行情提示需要重载 Web 静态资源。已存 HTML 要用显式 `feed.trendforce.reparse` 重读，启动时不隐式重抓。

UI 合成检查：`scripts/verify-trendforce-routing.mjs` 使用 Host 注入的无头浏览器，检查桌面/手机宽度、来源切换晚返回、完整旧链接、简介阅读、真实表格安全文本呈现、单观测无图表；不控制用户桌面。

### 2026-10-15 单位、当前报价与数据日期

公开标题只写「未税」。解析器改为 `trendforce-tables-4`，沿用各表自己的计价单位，不改已核对的数字：

- DRAM／NAND 现货，以及 DRAM 合约里的颗粒，仍是 `USD` / `chip`。
- DRAM 合约里的 SO-DIMM（DDR5 8GB、DDR4 16GB、DDR4 8GB）是 `USD` / `module`（条）。
- 内存条 `module`，显存 `chip`，晶圆 `wafer`，存储卡 `card`，SSD（OEM 合约和街价）`unit`，NAND 合约价 `chip`。NAND 合约标题里的 Memory Card/UFD 是用途，不是存储卡现货。

同一规格可以同时有两组 `is_current=1`：2026-10-05 的旧行（单位空，规格名带「· 日高點: 19.70」）和后来带单位的行；另外有 `period_key` 以 `unverified:` 开头、没有报价期的行。行情列表按规范化规格名只留带单位且有报价期的那一版。migration 68 把被取代的行标成 `is_current=0`，不删除行，不改数字。之后每次写入也会把这些旧行从当前拿掉。精确快照链接仍能打开旧表。

每一项价格直接带官网 Last Update 的月日。DRAM 等合约的半月期写成「8 月下半月」，和 Last Update 的 `08-31` 放在一起，不把 9 月 30 日的会员通知当成报价日。超过 7 天标「已过期」，例如合约价 `08-31`、SSD OEM `08-05`。不另加「更新时间」行。

已保存的 HTML 要用显式 `feed.trendforce.reparse`，或等下一次价表同步；解析版本变了才会写出新观测。生效需要同时重启 Web 和 Worker，浏览器再加载一次。不要重建数据库。
