# 信息摘选 V1

## 最新小时与执行状态（2026-10-06调度修复决定）

常规小时任务以实际执行时钟确定最新已结束小时，`scheduledFor`仅保留调度审计意义。先处理该小时（有冻结底稿时直接补编辑），再在独立8分钟墙钟预算内最多补一个旧小时；补编使用同一Harness的低优先级入口。旧小时优先最近缺稿，其次未读补全，最后旧正文升级，失败30分钟内不自动重复补编。显式选择小时仍可立即重试，不重抓已经完成的提炼底稿。20分钟单小时预算和检查点保持，退出补编预算不将已完成主时段误报失败。

同一Harness仍串行执行，增加可取消的优先级准入；已取消的等待项不会启动或处置正在执行的调用。交互请求优先于最新小时，最新小时优先于其他封闭任务，旧补编最低；不抢断正在执行的调用。领域阶段分别限制排队等待与执行（执行包括执行器准备），记录queueMs/executionMs和结束原因；执行截止从实际准入后开始，独立墙钟总预算仍有效。默认准入等待最多2分钟，低优先级补编最多1分钟。诊断耗时保存于阶段input的executionTiming，但模型输入与冻结缓存哈希不包含它；心跳续租并更新耗时。不得为此新建Agent、Runtime或并行模型执行。

小时目录列出窗口内所有已结束完整小时。没有处理记录显示尚未开始，不推断采集为空；排队提炼、提炼中、排队成稿、成稿中、成稿失败、已完成无正文和可读稿分别表达。发布指针与最近处理尝试分开，有旧可读稿时继续阅读并标明补处理失败。首次选最新可读时段，不按正文版本压过更晚旧稿；主动选未成稿小时显示该时段状态，不回退其他小时。页面轻量显示当前阅读期与所选日期的最新发布截止，保留阅读中换版不跳动和原有文章排版。

Harness返回的`turn/end`错误必须作为模型调用失败保留实际错误；不得退化为“没有返回回答”，更不得将中止时的部分回答当成完成稿。目录用固定`model-error`分类，不暴露供应商错误文本；底层阶段保留实际错误供本机诊断。没有明确余额或限流证据时不得推断额度原因。

## 方向文章（2026-10-05后续用户决定，覆盖下文主题正文方案）

新编辑版本 `brief-editorial-v3` 以方向文章为交付单位：稳定 key/label、文章标题、带事项引用的短导语、少量小标题和自然段。每段只保存实际采用的事项 ID，由程序继承冻结证据；同一事项的正文主要归属限于一篇方向文章，可在该文章的章节间合理分段，导语可复述正文事项。全部底稿不变，未采用事项不追加正文。单条社交重大传闻不能因金额刺激进入导语；作者研究保留核心论点与关键支撑，不复抄完整财务表、公司履历或名录，不用流畅行文补未知事实。引用事项允许只采用其中相关部分，不能因为引用 ID 而复述整组条款；标题、导语与正文各自保留必要作者归属、数字期间和计划状态，同一材料窗口不推导事情同时发生。

复用原封闭 Elucid Grok / DeepSeek Harness 编辑阶段。输入以短编号关联事项和来源，返回后确定性还原真实事项 ID；提供事项对应的冻结段落与来源元数据（12KB证据预算，另显式报告未纳入数量），缺失或未纳入的依据保留未知，不开放联网或 Host 工具。ready 复用同时比较当前编辑版本和事项输入指纹；旧 ready 稿通过固定 Worker 的 `mode=rewrite` 或版本升级，只重编冻结底稿，创建新不可变快照，不重抓、不重译、不重提炼。指定 snapshotId 时必须匹配所选小时及 workspace；失败不替换旧 ready 发布指针。历史 v2、日报成稿和引用继续可读。

阅读主序为方向→报告期→一篇文章。小时首次默认最新可读时段，版本不改变时间优先级；旧时段始终可手动选择。切方向保持相同时段；时段选择不拼接其他小时，没有该方向则准确空态。日报读取所选日正式冻结版本，不由前端拼接小时。新版文章使用独立阅读组件，段末来源直达站内原文，整篇文章提供收藏/引用，段落依据放入轻量菜单；旧稿仍按实际旧结构显示，不伪造段落证据。每个方向/报告期保留位置，阅读中换版只提示。版本校验、无溢出和条数减少不等于语义质量已验收。

2026-10-05 后续用户决定：后台逐项保存提炼底稿，前台每小时交付一篇已编辑的简报。整小时编辑在分批提炼之后进行，输出具体总览、方向章节和主题要点，跨来源合并同一事情并保留限定与冲突。常用方向为金融与市场、时事与政策、科技与产业，没有材料的方向不凑栏目。日报在小时主题基础上跨小时编辑，同时保留全部底层事项。

## 整小时主题编辑与来源直达（v2兼容决定，正文形状由上文覆盖）

复用 Worker 的 `report.hourly.extract`、Report Repository 和冻结的 DeepSeek Harness，不增加线程、业务 Agent 或 Runtime。封闭任务 `hourly-brief` 固定选择 Elucid Grok；提炼和编辑都通过同一 Harness 实例执行，无工具、联网和 Host 权限。可选 `AI_CENTER_HARNESS_HOURLY_MODEL` 覆盖小时模型，否则使用 Elucid 默认模型或现有 Elucid 主模型；Ask 的主模型配置保持独立。

`items` 始终保存全部已校验底稿；新增可选 `editorial`，ready 时包含 overview、overviewItemIds、overviewEvidence 和 directions/topics，主题保存 id/title/body/itemIds/evidence。模型只输出输入事项 ID，程序继承对应冻结证据，拒绝未知/重复主题事项 ID、无依据总览及空主题。未采用底稿不追加到正文。旧 JSON 无此字段仍可读取；旧小时底稿首次升级只做编辑并创建新快照，旧证据引用不变，不重读原文。无事项时可完成空简报；编辑超预算或失败保存底稿及 failed 状态“主题整理未完成”，不冒充正式小时简报。有旧 ready 版本时失败不得覆盖其发布指针。

整小时编辑最多接收160KB事项索引，不静默截断。日报最多240KB，包含小时主题及全部底稿；超限保留阶段与材料并明确失败，不能分批输出后冒称完成全局编辑。日报 `informationItems` 保留全部原事项，独立 `editorial` 是阅读正文；兼容前八项不作为全量正文。持续关注仍从底层事项选择证据。

单小时仍有20分钟墙钟预算，默认分批提炼最多使用前12分钟，为整小时编辑预留6分钟执行及2分钟准入等待；纯冻结底稿重编没有提炼阶段，编辑执行调用上限为12分钟，仍受20分钟总预算约束。低优先级补编独立8分钟墙钟上限，纯编辑最多6分钟执行与1分钟等待。剩余未读范围显式保留并由后续处理补齐。编辑阶段有独立缓存，失败输出不污染成功缓存。搜索使用最新已保存底稿，包括未替换旧 ready 正文的编辑失败版本；小时页面只展示 ready 正文，未完成版本在空态/处理情况说明。首次没有已编辑小时正文而已有日报时，直接读取已有日报。

默认先处理实际执行时的最新已结束小时，再从其余23小时内选择一个低优先级补编对象：最近缺稿、部分覆盖、旧正文升级，完整当前稿采用轮转检查迟到材料。失败30分钟冷却；指定小时仍只处理所选一小时。

固定小时 Job 的主时段遇到 editorial failed 时报告处理失败并进入原有重试机制；后台补编失败单独保留阶段/快照诊断，不重试整轮已完成的最新小时。已保存底稿、阶段和旧 ready 发布结果仍保留，不能因底稿保存成功就将主时段主题编辑任务标记成功。

小时引用使用不可变 snapshotId，Context Service 解析冻结总览、方向、主题及逐项证据，不创建应用聊天会话；完整底稿通过既有只读搜索与证据工具按需读取。日报引用同时支持新主题及原底稿，历史引用不随发布版本移动。

每个主题旁按材料身份去重显示独立来源编号，普通点击直接进入已有站内文章路由。来源身份由冻结材料的 sourceRefs 解析，模型不能编 URL。媒体通过按 externalId 查询的只读 Service/Repository/API 获取，不能依赖列表缓存或为阅读触发抓取；隐藏材料的明确溯源阅读仍可获取已保存文章。冻结段落、版本与上下文保留在次级“查看提炼依据”；外链明确标为“前往原站”。沿用原文阅读的返回路由和滚动恢复。

以下较早的原子信息编排与默认证据弹窗说明，仅描述兼容历史版本；本节覆盖新稿的阅读与编排规则。迁移不改历史 migration，不覆盖旧日报，不删除底稿。

## 时间与保存

窗口左闭右开，小时按 UTC 整小时划分，界面按 Instance 时区显示。归属使用 publishedAt，缺失时使用 createdAt；这表示来源发布/入库时间，不声称实际事件恰好发生于该小时。采集、获得、冻结与生成时间分别保存，迟到材料显式标记。

Worker 注册 `report.hourly.extract`，每小时检查最近 24 个已结束小时（停机不逐档派发 Job），补处理迟到/换版材料；日报还会用自己的冻结材料补齐窗口内事项。更早的迟到材料可通过指定小时重跑。相同正文版本、段落、覆盖与流程复用小时结果；新材料创建新的不可变快照，旧引用继续有效。空窗口与来源失败分别表达，未读材料量不能解释成没有事情发生。

小时事项保存 id、sentence、evidence、occurredAt、processedAt、supersedes。每个 evidence 固定 snapshotId、materialId、paragraphId、materialHash 和 materialVersion。快照保存完整已存原文，阅读分批且记录完整/部分读取；单批/总调用预算只影响本轮覆盖，不截掉已成功提炼的事项。原文版本可以比阅读片段完整，不能冒称读完。

阅读预算留下部分覆盖版本后，下次检查创建新快照，复用原材料已完成批次、只调用缺失批次，直到完整读取收录材料；旧部分版本仍然可溯源。非整点日报截止支持独立边界快照，独立小时列表只返回完整一小时的窗口。

后续批次超时、断线或输出校验失败时，已成功且证据校验通过的批次发布为部分覆盖版本，失败批次不计入读取范围；第一批失败且无成功检查点仍按失败处理。恢复历史失败或失效租约时，优先读取原冻结输入和匹配的成功检查点，先发布可读结果，再由后续处理补齐未读范围；迟到材料不能让成功检查点在恢复阶段失配。HTTP只通过已注册的小时Job入队，不在读取接口生成内容或直接改库。

## 日报与兼容

新流程继续使用 DailyReport、DailyBrief、Report Repository 和同一 Harness 的 closedContext。不改 Ask/Article Runtime，不增加 Agent、联网或 Host 工具。`informationItems` 是新稿权威清单；旧 items 前八项只作兼容概览，sections 保留旧稿读取。旧 V1/V2 分析与引用保持可读。

日报编辑只接收信息事项，逐批合并与排序。合并输出必须提供输入事项 ID；程序继承其全部证据，拒绝未知/重复 ID，未被编辑引用的事项自动保留。限定（作者自报、计划、仅部分开放等）不可丢失；冲突和更新不能误并。模型合并后的句子仍需实际样本验收，ID 与段落校验只能证明来源身份，不能证明语义。所有事项保存，显示折叠与首页预算不删除事项。持续关注问题仍只更新明确启用的配置，定向读取已冻结证据。

单轮编排约40KB事项索引。大清单分批处理，合并后能进入单轮预算时再全局编排；仍超预算时明确标记跨批语义去重/全局排序尚未完整完成，保存所有事项。持续关注先按问题选择相关事项，再定向读取14KB以内原段落，保留证据预算遗漏数量；旧判断仍只作假设。

## 访问

### 简报阅读界面（2026-10-05）

现有 `report` 路由显示为「简报」，内部是小时更新 / 日报精选。首次默认小时更新，设备身份隔离的本地状态记住所选视图、事项已读和收藏；状态只存显示签名，不保存正文或证据，不跨设备同步。授权失效、退出或切换设备清除相应缓存。打开来源只标记这条简报，不写关联整篇文章已读。相同句子及同一材料/段落/正文版本的事项，即使换了快照ID，也沿用已读与收藏；更正正文或证据版本有独立显示身份。

`apps/web/public/brief-page.js` 共用视图状态、信息行与固定证据面板。小时按组倒序，默认每组四条；日报读取全部 `informationItems`，超过二十条可展开，没有主题字段则保留既有编辑顺序。不从来源名称猜主题，不额外请求模型。旧稿沿用原有分析与引用渲染。

新增只读 `GET /api/v1/reports/hourly/index?startAt=...&endAt=...`：严格校验七日以内窗口，Report Service 经 Repository 返回实例时区、完整小时的发布快照ID、生成时间、数量、最近处理状态和覆盖计数，不返回正文。已发布快照与最近失败/进行中的重试分别表达；失败不取代旧有效版本，日报边界快照不进独立小时目录。新冻结记录保存处理窗口，旧完成版本按 digest 窗口兼容读取。

首读按清单分批获取不可变 `/hourly/snapshot`（最多三个并发），每份快照读取完整事项，不受小时搜索单页100条限制。页面可见时每60秒只检查元数据；离开页面/切后台暂停，在线恢复检查。正在阅读、展开来源或选择文字时只提示，主动接受后换版；日报修订通过轻量日报目录发现，主动读取新版。请求代次隔离晚到响应，检查更新不创建Job。仅页面顶部无阅读操作时可以自动接收小时结果。

`GET /api/v1/reports/daily/brief/window?date=...&revision=...` 按指定成稿版本读取已冻结统计窗口与时区；缺少历史记录则返回null，不按当前配置伪造旧稿窗口。只读窗口响应不含材料正文。来源默认显示支持段落、真实出版商/作者与原文入口，上下文及时间/快照信息按需展开；材料数按materialId去重，不声称独立确认。桌面右面板、手机底部面板复用宿主dialog、焦点与滚动锁。

样式限定 `.brief-*` / `#report-list.brief-page`，保留全站600/840/1200px导航规则；1440px以上才展开辅助栏，1200px附近保持单阅读栏，正文不无限拉长。主操作至少44px高，长句完整换行。管理与重试收进更多，仅现有桌面权限允许生成，不以屏幕宽度授权。

2026-10-05后续用户要求阅读优先：首屏仅文字切换、日期和更多，沿用信息流页边距与浅分隔线，不套整页卡片。搜索、未读、收藏、处理数量、时区、检查时间、设备说明与生成管理进入更多；成稿/冻结/统计窗口按需展开，手机不重复前三条。每条默认显示正文和来源，其余操作展开使用。无小时结果但已有日报时首读已有日报，小时空态提供日报入口。V2旧稿保留原文叙述与限定，逐项引用沿用原成稿版本；缺逐项证据时使用App的简洁兼容渲染。加载状态在搭建或切换视图前设置，不能先显示未发布再显示已有日报。小时清单只将仍持有效租约的运行记录呈现为正在处理，过期租约作为失败状态读取，不写回数据库。

HTTP 只入队固定 Job；手动生成仅桌面权限。已授权设备可读小时列表、指定小时和冻结证据。证据直接返回对应段落、相邻上下文及原文入口，日报可直接打开同一快照，无须先跳小时再找文章。Ask 通过只读 Domain Tool 查看指定时间窗口的摘选，再按 snapshotId 定向读取证据，再自行决定是否继续搜索；不设置 Intent Router。

业务写入与 Outbox 同事务。前向 migration 38 新增小时版本表，39 保存当前小时发布指针；快照内容不变，失败恢复可重新指向原有效版本，历史日报重写不得替换较新小时结果。旧已完成日报不自动覆盖；新任务使用新流程。该专项不替代 0.2.0 发布门槛，真实提炼语义和持续运行仍需验收。
