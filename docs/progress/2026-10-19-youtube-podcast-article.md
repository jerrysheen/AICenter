# 2026-10-19 YouTube 播客正文

单集「展开全文」原来把 YouTube 字幕原样放在 `<pre>` 里：英文，大约每 2 到 3 秒一行时间戳。15 集里有 12 集是自动字幕，下一行会重复上一行的后半句。摘要仍由 Gemini 生成，这次只换正文。

这是用户为 YouTube 正文单独批准的例外。标题、摘要、关键句，以及其他所有翻译，仍只用 Gemma 26B（`gemma-4-26b-a4b-it`）。正文失败、豆包未登录或页面改版时，不自动改走 Gemma、Gemini 或其他服务。

## 开关

总开关 `AI_CENTER_YOUTUBE_PODCASTS` 仍要打开。正文开关是 `AI_CENTER_YOUTUBE_PODCASTS_ARTICLE`，默认关闭。关闭时新集仍把原字幕放进正文，和以前一样。

打开后，每天最多处理 `AI_CENTER_YOUTUBE_PODCASTS_ARTICLE_DAILY` 集，默认 2，允许 1 到 8。计数按 Asia/Shanghai 的日历日，从这一集真正开始整理时算起。同一天重启会接着做已经开始的集，不重复占名额。已经整理完、原字幕没变的集会跳过，所以重复跑是安全的。已入库的 ready 集也走这个限额回补。

英文标题和摘要里的英文关键句不看这个开关。每轮用 Gemma 补译，默认最多 8 条，环境变量是 `AI_CENTER_YOUTUBE_PODCASTS_TITLE_DAILY`（1 到 30）。

## 整理方式

1. 本地去掉自动字幕的滚动重复。比较不区分大小写，重叠至少约 12 个字符，或至少两个词，并且落在词边界上。对不上的行整句保留，人工字幕的词不会被删。时间戳只留在说话人切换，或距离上一次标记大约 45 秒的位置。
2. 按句末或 `>>` 说话人切换切开，每段大约 1 万到 1.2 万个字符。不按时钟硬切。最后一段可以短一些。`Mr.` 和小数不会被当成句号。
3. 使用已有的 `packages/connectors/src/doubao/chat-browser.js`。它通过 bsk 驱动服务器上已经登录的 Chrome。第 1 段带完整要求：整理成简体中文文章而不是摘要，加小标题和时间，标出发言人，术语保留英文，广告缩短但留下赞助方和代码。后面的段在同一个对话里只写「第 N/M 段，沿用格式」。每一段单独打开一个 bsk 会话，用完就释放。
4. 读回的文本会去掉「本回答由AI生成……」，以及末尾几行推荐追问。
5. 失败只重试这一段，最多 2 次。没确认发出的可以重发。已经发出但没读到回复的只重开该对话来读，不重发。还不行，就带上前一段的结尾，在新对话里补这一段。每段的进度写在 `article_state`，重启后按原分段继续。
6. 豆包未登录、输入框不存在，或这一段用尽重试时，正文先显示去重后的原文，`article_status` 为 `pending`，页面标「待整理」。未登录或页面改版会停掉当天剩下的正文整理，避免一直占着浏览器。第二天再试。

## 页面和数据

整理完成的正文按 Markdown 显示小标题、段落和发言人，替换原来的「展开全文」。原字幕不再显示。原字幕仍在 `youtube_podcast_episodes.source_transcript`，用来重跑。

migration 88 `youtube_podcast_article` 只加五列：`source_transcript`、`source_hash`、`article_status`、`article_state`、`article_day`。空号仍是 63、79、80、82。不要重建数据库。需要同时重启 Web 和 Worker，浏览器再加载一次。

## 另外三处

- 标题以前只在整篇摘要不像中文时才翻译。中文摘要配英文 `titleZh` 会留在页面上，例如 Odd Lots · Don Wilson。现在标题本身不是中文就单独交给 Gemma。摘要里的英文关键句同样处理。摘要提示也要求标题和关键句用简体中文。
- `transcribe is not a function` 已在主线修复：一轮开始会确认转写函数，缺失时不下载音频，有字幕的集照常入库。曾经因为这句错误被跳过的集，下一轮会再收一次。
- Gemini 摘要遇到 HTTP 503、500、429、配额或连接超时，会在同一次摘要调用里换密钥重试。默认再试 3 次，环境变量 `AI_CENTER_INVESTOR_DIGEST_SUMMARY_RETRIES`，范围 0 到 6，间隔 1 秒、2 秒、4 秒，上限 8 秒。同一次调用仍失败，才给这一集加一次尝试；满 3 次改为跳过，下一轮不再自动收。这次不改这条策略，也不清已有的尝试次数。
