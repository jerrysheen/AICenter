# 媒体文章阅读语言稳定性修复

用户报告阅读中突然由中文变成英文，授权定位并修复。用户随后明确暂停正文图片功能；本轮撤回图片采集、配置、接口、展示与尚未上线的 migration，没有向运行库写入图片或启动图片采集。

## 原因与行为

`readFeed`只在正文完整、extractor/revision匹配时投影全文译文。后台采集或元数据更新会让这份投影暂时为空或未完成；原阅读页的`ready ? 中文 : 原文`分支和列表展开的同类分支因此自动显示英文。正文/译文的版本校验应保留，修复位于客户端阅读投影。

`mediaAsItem`透传bodyHash与snapshotRevision，现有`media-feed.js`增加一个当前阅读会话。已载入的完整中文在后台失效时继续显示；新正文版本译文就绪后提示，由读者明确切换。中文及逐段对照中的缺失译文显示进度占位，不用英文顶替；英文由“原文”或“逐段对照”的原文栏显式展示。列表展开复用同一段落语言投影。再次打开文章默认中文。

内存仅保留当前文章及最新投影，换文章、退出配对或授权失效时清空；不增加持久全文缓存、不修改数据库/译文历史、不新增Worker或模型请求。复用已注册静态资源，不需中断运行中的enrich任务。

## 验证

`test/media-reader-session.test.js`覆盖ready→partial→译文缺失→列表移除、正文换版与明确接受、缺段与旧哈希译文、显式原文、换文章/换设备/失效授权以及真实mediaAsItem的版本透传。静态HTTP测试确认同一UI版本能加载包含阅读逻辑的media-feed.js。最终全仓`npm run check`通过709/709，`git diff --check`通过。现有服务的app.js与media-feed.js均返回200，新导入与阅读函数已在线，health正常；运行库schema仍为37、图片表为0。Host核对记录位于`media-reader-acceptance.json`，不提交运行库或原站全文。

本轮未通过桌面自动操作模拟用户浏览。此前图片功能不进入本轮交付，图表图片仍需用户查看来源核验。
