# TrendForce 内容归位与硬件报价

## 本轮范围

按用户批准的内容类型方案实施：来源管理保留 TrendForce；洞察、预测、供需分析进入媒体科技产业，会员目录明确为报告简介；实际 DRAM/NAND/SSD 报价进入全球行情的 AI硬件价格，存储卡属于其他存储参考。没有新增信源、采集频率、复杂告警、Agent 或数据库体系。

## 实现

- 原 TrendForce Collector、Source 和 Worker 仍是唯一采集入口。一次抓取返回文章和直接从 HTML 表格解析的结构化报价，Feed 的分流 Port 调用两个 Service。已验证洞察继续按 ID 跳过，媒体抓取任务不再请求 TrendForce；翻译/标签复用既有媒体补充任务。
- migration 40 新增快照、报价版本、快照行引用和旧媒体身份关系；已执行旧迁移不修改。原始 HTML/旧 Markdown 保存到 Instance blobs，数据库只存相对路径。输入与页面输出都进行 Contract 运行时校验。
- 规格身份保留 SSD 品牌、接口、型号与容量。高低均价保留原站列名，半月/季度与现货有效期分开；来源更新和采集时间分开。未知币种、单位、报价期保持空值、待核验，不能算可比涨跌。
- 同期同值重复引用已有观测，新报价期追加；同期 A→B→A 保留全部修订和前版链接。不同原始快照仍能定位，单期无历史；真实多期即使单位未核验也能读原值，但不生成可比变化或股票 OHLC。
- 来源筛选在分页/计数前执行，浏览缓存、请求和晚返回校验包含来源及设备。旧 TrendForce 浏览选择恢复为科技产业来源筛选；全文、部分正文和报告简介独立标识。
- 迁移保留原 Capture/ContentItem、已读、隐藏、收藏、Tag、引用和 URL；媒体关联旧身份。两条旧价表链接打开整表快照，提供“查看AI硬件价格”。日报读取真实完整度，分页前排除已分流旧记录，保留冻结历史日报。

## 本机数据

执行前通过 SQLite 在线备份保存 Instance 数据库，备份在忽略的运行目录中。注册迁移 handler 通过只领取本任务的 runner 执行，不恢复或终止其他 Job。

- 原有 51 条：14 篇文章、35 条报告简介、2 张价表。
- 49 条迁入媒体，2 张旧价表作为 legacy-text 快照，结构化保留 41 个规格。未记录全文提取证据的旧文章标部分正文；未补造被覆盖的历史。
- 原文、Capture、旧用户状态及旧 Tag 的迁移前后指纹相同。重复执行返回 0 快照 / 0 文章。
- 新代码的隔离 HTTP 实例回读生产库：现行准入/隐藏规则下科技产业 TrendForce 可见 36 条（13 部分正文、23 简介），原 49 条迁入记录均保留。41 个旧报价因币种/单位/报价期待核验，全部保持 pending。
- 来源目录保留公开 TrendForce，内部 collection Source 不暴露；旧价表 original API 回读 200 并返回整表快照。
