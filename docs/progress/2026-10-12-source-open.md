# 简报来源一点打开

## 目标

小时报和日报详情里，点要点或 ref 角标就能打开原文。多个来源直接铺在要点下面，不再先打开下拉。

## 决定

只改前端。不改数据、接口和生成。站内文章仍走原来的 `readSavedSource`。没有站内文章、但有 http(s) 链接时，用新标签打开（`target=_blank`，`rel=noopener`）。多个来源默认展开，一行是「来源名 · 标题」，12px 灰色，长标题换行。点角标滚到并高亮对应那一行。来源行和角标在 `touchstart` 上停住冒泡，避免被小时横滑当成切小时。

## 改动

- `apps/web/public/information-tree.js`：去掉模块上的「N 篇 · ref」下拉，也去掉日报里「查看信息」那层折叠。一个叶子直接打开，多个叶子平铺。小时阅读行点标题或〔1〕即打开；`item.sources` 多于一条时在行下平铺。
- `apps/web/public/brief-page.js`：旧简报的〔n〕和「来源 N」目录改成同样的一点打开 / 平铺。提炼依据对话框还在，但不再是打开原文的必经步骤。
- `apps/web/public/styles.css`：角标和来源行最小高度 44px。

## 验证

`npm run syntax` 通过。`node --test test/hourly-unread.test.js` 14 项通过，其中 3 项覆盖小时单来源、小时多来源、日报单来源、日报多来源，以及没有成稿时打开模块不再出现 ref 菜单。来源行会拦住 touchstart，横滑不会切小时。

另外用真实样式表在 1280px 和 393px 各截了一张静态样例。样例没有接数据库，点击路径以单测为准。

## 遗留

当前小时阅读接口一条就是一篇，多来源列表出现在日报段落、模块的多篇叶子，以及阅读条目自带 `sources` 时。`app.js` 里很旧的「原文证据」折叠还在，树阅读不再经过它。静态资源更新后，已经开着的 Web 页面要刷新一次。
