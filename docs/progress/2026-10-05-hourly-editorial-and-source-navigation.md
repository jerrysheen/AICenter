# 整小时编辑与站内来源直达

用户本轮决定：每小时交付总览、方向和主题，而不是把提炼底稿当作正文。使用现有 DeepSeek Harness 接 Elucid Grok，不新建线程、Agent 或 Runtime。先更新 `information-digest-v1.md` 的阅读/保存边界与旧稿兼容决定，再实现。

## 已实现

- 现有 `report.hourly.extract` Worker 流程先分批提炼，再通读整小时底稿进行语义编辑。`hourly-brief` 封闭任务固定选 Elucid Grok（当前 Instance 为 grok-4.7），模型选择和凭证检查一致；公开 Ask 不能用该 task 字段切模型，小时任务不带应用 sessionId。沿用冻结 dsh 0.1.6-alpha.2、同一 Runtime 和执行队列，不新增外部执行器或联网工具。
- `items`/`informationItems` 保存全部底稿，另存 ready/failed `editorial`。总览与主题只引用输入事项，程序继承冻结证据，拒绝未知/重复 ID、无依据总览、空方向；未选事项不追加正文。小时新稿有14分钟提炼、最多6分钟编辑的总预算分配，未读覆盖始终显式。编辑失败不取代旧 ready 发布版本，失败底稿仍可搜索。
- 存量小时直接复用底稿编辑、创建新不可变快照，不重读原文或改旧证据。日报在小时主题上编辑跨小时事项，同时完整保留底稿与追踪问题依据；旧日报保持原成稿，不自动覆盖。
- 主来源按钮按材料身份去重，每份直接进入已有站内阅读路由，较多来源展开目录；冻结段落与上下文为次级“查看提炼依据”。媒体可按 externalId 直接读 Service/Repository/API，不依赖列表缓存，不因阅读触发抓取；媒体文章刷新后的恢复也复用该入口。原站链接明确标为“前往原站”。
- 小时引用 Contract/Context 解析不可变快照及主题证据，日报主题和底稿引用均可解析。正文保持信息流字体/边距，管理收起；未完成小时不以零碎清单冒充正文，有日报时首读日报。

- 最终 `npm run check` 770/770通过。封闭 Harness 路由、跨来源合并/未采用底稿、编辑失败保留旧发布指针、重试缓存、旧底稿升级、日报主题引用、小时 Context 引用及跨 workspace 读取都有确定性验证。
- 真实 Harness 合成样本：3条底稿整理成2个主题，作者自报、预计量产、仅部分测试用户开放、未披露交付等限定保留；全部主题证据可解析，使用隔离 SQLite，不写生产数据。
- 合成浏览器检查覆盖13种宽度、两种视图；375/390/502px 首屏可读总览，底稿13条时只渲染选入的12个主题，未采用事项不进入正文。验证未缓存媒体直接阅读、返回位置、次级证据、旧日报、换版通知、过期响应及授权清理。

- 另选实际已保存的 DCD 媒体文章进行390px冷缓存验证：信息流列表为空时仍可按包含斜杠的 externalId 恢复站内全文，9个段落、2196字符与原存储投影一致；无抓取副作用、横向溢出或脚本错误。
- 运行服务回读：16—22点六份存量小时均已完成主题编辑，包括被并发服务重启中断的16—17点任务由现有 Worker 恢复完成。当前22—23点正在按既有小时调度处理；尚未读完的来源仍展示实际覆盖，不把主题完成等同于来源全部读完。

生产已有小时的底稿通过同一固定 Job 后台补编；阶段、覆盖与最终结果均保存在原 Repository 中。持续来源覆盖及模型语义准确性仍需长期验收；本专项不等于0.2.0整体发布通过。没有改历史 migration、删除数据或提交整个工作区。
