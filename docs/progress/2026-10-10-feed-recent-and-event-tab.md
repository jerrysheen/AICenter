# 信息流最近不重绘，事件概率独立标签

## 根因

`#feed` 的「最近」是本机浏览记录，最多 80 条，列表本来就按 12 条分页。它没有自己的接口。卡顿来自主线程：

- `visibleFeedItems()` 在选出「最近」之前，每次都把已加载的 X、雪球、手工和官方列表映射成卡片。`formatTime` 每次新建 `Intl.DateTimeFormat`。翻过「全部」或补过重点窗口之后，这份列表会到几百条，算完又丢掉。
- 实时推送（采集入库、信息准备、译文删除）只要 X / 雪球曾经加载过，就会再拉一页并合并。每次 `loadXFeed` / `loadXueqiuFeed` 在开始、合并后、打标后和 `finally` 都调用 `renderPosts`。`renderPosts` 用 `replaceChildren` 拆掉整列 DOM，并再走一遍映射和全量排序。人停在「最近」时，推送并不改变浏览记录，列表仍会被反复重画。
- 不是「最近」接口慢，也不是一次插入上千个「最近」节点。

## 决定

排序规则不变：最近仍按 `viewedAt` 从新到旧；其他栏目仍是未读优先，再按收录或发布时间。

- 「最近」只读浏览记录。「重点」「官方」「社媒」也不再先建一份用不到的列表。输入没变时复用上一次排好的结果。
- 当前在信息流里、而且这个栏目不显示 X / 雪球时，后台重拉不调用 `renderPosts`。数据仍合并进内存，切回「全部」用得到。
- 「最近」行没变时保留已有 DOM。时间格式化器只建一次。

事件报价仍用原来的快照和「较昨日」。全球行情子标签末尾增加「事件概率」。只有这个标签显示 `#global-events`。全部、AI硬件和其他分类不再带这段。首页「事件概率 ›」打开 `#market/global?tab=events`，刷新仍停在该标签。

## 验证

`npm run syntax` 与 `npm test`。失败数不超过 main 基线。
