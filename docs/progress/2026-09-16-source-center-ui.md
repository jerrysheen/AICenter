# Source Center UI

## 目标

在不改变现有信息流、交易页和鸿蒙五项底部导航的前提下，把已接入的 X、B站、市场看板、
全球资产和 Web Search 组合成统一的来源中心，并为后续公开 Source 保留自动展示位置。

## 决定

- 来源中心进入五项主导航；尚未正式工作的「日报」回到工具页，因此鸿蒙底部仍保持五项。
- 页面只消费 `/api/v1/sources`、Source Manifest 和 SourceSnapshot；未知的公开 Source 会自动进入对应分类。
- 原有信息流与交易页继续负责完整操作，来源卡片只提供状态、摘要和稳定入口。
- 手机端使用单列卡片、48px 以上触控入口、文本状态和安全区；桌面端扩展为三列。
- 未接入接口以「待接入」显示，不伪造可用状态或样例数据。

## 改动

- 新增主导航「来源」和 `#sources` 页面，页面变化无需经过二级入口。
- 桌面侧栏将「信息」收进 `Sources` 分组，避免两个同属来源域的平级入口割裂；鸿蒙/手机底栏继续保留「信息」快捷入口。
- 按信息、市场、检索、待接入分组展示来源。
- 来源目录进入时只读取目录，不主动逐个刷新快照；用户点击「更新状态」后才读取状态、更新时间、warning 和简要数据规模。
- X / B站卡片返回原信息流，美股 / 亚洲 / 全球资产卡片返回原交易页，Web Search 进入联网问答。
- 预留新闻与 RSS、公司公告、宏观日历三个未来接口位置。
- 修复静态资源进程内缓存不随文件变化失效的问题，开发中的页面更新无需再次重启服务。

## 验证

- 静态资源测试校验来源页面和加载逻辑存在。
- Source API 测试继续覆盖 Manifest 目录和 Snapshot 读取。
- `npm run check` 覆盖语法、契约、架构边界、鸿蒙脚手架和全量测试。
