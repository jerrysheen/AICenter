# 总览首屏、A 股走势和报价过期

线上总览大约 14.5 秒才出来。云端没有那台 Windows 服务器上的库，下面的毫秒是本机夹具，不是那 14.5 秒的回放。上线前在服务器上跑测量脚本。

## 首屏

三条根因叠在同一次请求上。

`composeHomeBootstrap` 先等目录，再逐小时读阅读，再等日报、行情和官方看板。阅读 `present()` 对每条条目各查一次节点、两次内容和一次来源。外层把窗口里的小时版本逐个打开。行情读板时，目录里没有的自选代码会在这次请求里等外部报价。

现在：

- `home.bootstrap.snapshot` 仍由 Worker 每分钟组包写入 `runtime_snapshots`（键 `home-bootstrap`）。组包里目录之后的阅读、日报、行情、看板一起开始。各段毫秒写在快照的 `timings`，日志是 `[worker] home-bootstrap`。
- Web 只写出已经准备好的缓冲区。`Cache-Control` 是 `private, max-age=0, stale-while-revalidate=60`。`refresh=1` 仍不在请求里重算。浏览器对这份地址继续 `cache: 'no-store'`，避免昨天的正文被当成今天。
- 页面冷启动同时请求快照、目录、小时索引、行情总览、日报和官方看板。小时明细仍放在首屏之后。
- `present()` 和 `forWindows()` 把节点、内容摘要、来源名称各查一批。
- 自选代码没有缓存时，看板立刻返回，`pending: true`，价格先空着。后台补拉进 45 秒缓存。页面在 `pending` 且没有价格时显示加载圈，并隔 800 毫秒再读，最多 8 次。

## A 股走势

雪球报价条目本身没有 K 线，`sparkline` 一直是空数组。Worker 生成 A 股看板时，对还没有走势的雪球代码再读日 K，把收盘价写入 `sparkline`。同一代码在同一个上海交易日只拉一次；失败留下上一份。每一轮最多补 10 只，整轮用 `AbortSignal` 限时。当天最后一个点改成当时的实时价。首屏快照保留每条最多 30 个点，以及 `asOf`。后到的一份若缺走势或成交时间，页面沿用已经画上的那条。

## 已过期

整板 `fetchedAt` 超过 180 秒，或者快照带 `stale: true`，页面就把整板写成红色「已过期」。Yahoo 一慢，`market.boards.snapshot` 又要等美股成功才写后面的看板，快照停在旧的 `fetchedAt` 上。

现在四个看板各自读取、各自超时（`AI_CENTER_MARKET_BOARD_TIMEOUT_MS`，默认 12 秒，允许 1–60 秒），成功一块写一块。总览只等焦点看板（北京时间白天是 A 股，其余是美股）。美股常规交易时段仍会在新鲜度不够时把任务标失败，但已经写好的其他看板留着。日志是 `[market] boards us=…ms asia=…ms cn=…ms global=…ms failed=…`。

页面有成交时间时，用报价里最新的 `asOf`。只在盘中判断过期：报价自己的 `session` 优先，没有时美股按美东常规时段，A 股和港股按交易日加时段。休市写成「收盘 · 时间」，不标红；整块看板都休市时 `stale` 为 false。盘中超过 3 分钟没有新成交，才标「已过期」。某一条自己的 `asOf` 旧了，只给那一条标。

组包仍把各段毫秒记在任务结果和 `[worker] home-bootstrap` 日志里。写进 `runtime_snapshots` 和浏览器响应的正文不再带 `timings`。阅读先读原始小时，只给有条目的前 4 个小时做 `presentMany`。自选补拉超过 10 秒就中止。快照 `generatedAt` 超过 5 分钟，首页写「数据更新延迟」。`pending` 时页面会再请求。

## 本机基准

夹具是 168 个小时版本、每小时 15 条，外加 8000 毫秒的同步报价等待，用来代表请求路径上的外部拉取。SQLite 在这只小文件上很快，所以查询毫秒不能当成线上库。次数才是本机能说明的部分。

```
node scripts/bench-home-first-screen.mjs --hours 168 --per-hour 15 --quote-wait-ms 8000 --runs 3
```

| | 改动前 | 改动后 |
|---|---|---|
| 首屏 | 8002.0 ms（查询 2.0 ms，498 次读取，报价等待 8000 ms） | 1.1 ms（查询 1.1 ms，5 次读取，报价等待 0） |
| 七日 present | 38.0 ms，10416 次读取 | 18.1 ms，22 次读取 |

## 服务器测量

在仓库目录执行。数据库路径按这台机器的数据目录改。Web 用本机地址，回环会被当成桌面。

```
node scripts/measure-home-perf.mjs --db data\ai-center.db --hours 24 --base http://127.0.0.1:8787 --log data\logs
```

脚本读最近若干小时 `jobs.type = home.bootstrap.snapshot` 和 `market.boards.snapshot` 的耗时与失败率。响应正文不再带 `timings`。`--base` 再量一次 `GET /api/v1/home/bootstrap` 和五个模块并行。`--log` 附上最近的 `[worker] home-bootstrap` 和 `[market] boards`。

不新增 migration。76 仍是 `twse_monthly_revenue`。不要重建数据库。需要同时重启 Web 和 Worker。浏览器再打开一次总览。
