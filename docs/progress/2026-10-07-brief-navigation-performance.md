# 手机简报入口与加载修复

## 问题与决定

用户反馈手机简报加载慢，进入「历史简报」后落到陌生旧页面并停留旧日期。实查历史按钮直接绕过tree-v3路由，挂载legacy阅读器；首次进入下载七日全部信息提炼稿约2.2MB，等待标签后逐个请求本期根模块，挂载结束又立即重复检查同一七日目录。既有缓存仅在当前树实例保留单节点。

当前、历史和指定日期统一使用同一个树阅读器；历史增加日期/刊期选择及返回最新入口。旧版稿件只从明确的旧版存档进入，停止更新标识和返回历史按钮一直可见，新增archive hash并兼容浏览器返回。旧稿和引用不删除、不重新生成。

## 改动

新增可选reading目录投影和不可变刊期批量根模块GET，复用Report Service/Repository/workspace与运行时Contract校验。保留原完整接口；协商gzip且no-store。客户端30秒设备会话内目录缓存/在途合并，节点400个、刊期8份内存上限；退出和身份切换清除，不持久化个人数据。标签异步加载，不阻塞正文；首次挂载不重复检查。批量接口在滚动升级中未就绪时回读原不可变节点接口。存档先读索引，不先下载旧小时全部正文。

## 验证

新增轻量投影/不可变根覆盖/跨workspace隔离、GET输入校验与gzip/no-store测试。`npm run check`最终899/899通过；首次运行中新压缩测试样本小于压缩阈值，修正样本量，另有既有极短定时器测试受并行负载超时，独立复核及完整重跑均通过，未放宽生产或测试超时。

新增`node scripts/verify-brief-navigation.mjs`，验证当前→历史→存档→历史→最新及浏览器返回、热缓存请求数、批量读取与390/1440px布局。需要现有Host的UIUX_RUNTIME_PACKAGE/UIUX_BROWSER环境，所有API只读、阻止业务写入。截图复核另发现首次占位期间重复挂载会提前调用legacy刷新、对未建好的控件写value；增加控件就绪判断，脚本同时捕捉toast中的被接住异常，最终toast和pageerror均为空。断网读取失败另提供明确重试按钮。

只读预览把Tag接口延迟3秒，正文仍先于Tag出现；当前→历史→存档→返回过程仅一次目录、一次最新刊期批量及一次旧稿索引请求。没有为了补出结果而调用模型或重编简报。

生产先SQLite在线backup，通过Repository CAS暂延queued领取并暂停原enabled schedules，等待在途小时生成和采集自然结束后写原启动器restart.request。已确认Web/Worker正常重载、36条暂延任务全部恢复，原schedule恢复；未强杀模型、未重置running或attempt。私有证据位于Instance的brief-navigation-reload目录。

正式API回读：原完整七日响应约2,263,072字节；reading目录解码773,622字节、gzip传输147,974字节，本期19模块批量正文gzip 6,064字节。旧版本没有启用gzip，原首屏七日请求约2.2MB；当前首屏约154KB和两次Report GET。实际网速/手机首屏秒数没有据此臆测。正式浏览器导航脚本共4次Report GET（目录、两个不同刊期、旧存档索引），返回最新复用缓存，无逐根node请求；390/1440px无溢出、无脚本错误或错误toast，截图人工复核通过。浏览器视口验证不冒称用户手机真机验收。
