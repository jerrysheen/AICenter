# 第一次制作：连接与用户行为原型

## 目标

验证电脑与手机之间的局域网直连、首次配对、长期授权、信息发布、实时同步和最小用户行为指标。

## 实现范围

- 建立 Node 本地 Web 服务，默认端口 `8787`。
- 提供响应式桌面和手机页面。
- 自动识别本机局域网 IPv4 地址并生成本地二维码。
- 使用 10 分钟、一次性配对码换取长期设备授权。
- 设备 token 仅通过 HttpOnly、SameSite Cookie 发送，数据库只保存哈希。
- 使用 SQLite 保存设备、配对码、信息和行为事件。
- 使用 SSE 将新信息实时同步到已经打开的页面，并由浏览器自动重连。
- 桌面端可以查看 24 小时行为指标和撤销设备。
- 建立第一条系统测试信息。

## 验证证据

- `npm run check` 通过，包含 6 项确定性测试。
- HTTP 集成测试覆盖健康检查、配对、发布、SSE 事件和服务重启后的数据持久化。
- 本机通过实际局域网地址访问页面返回 HTTP 200。
- 未配对的局域网请求返回 HTTP 401。
- 使用一次性配对码后，局域网客户端获得 `device` 身份并可读取信息流。
- 从桌面撤销验证设备后，原凭证再次访问返回 HTTP 401。
- 实际启动时识别到一个手机访问地址；具体地址可能随网络变化，以启动输出和页面二维码为准。

## 安全边界

- 第一版仅用于同一局域网，不配置公网入口。
- 只有 Web/API 端口监听局域网。
- 配对二维码不包含长期 token。
- 当前为局域网 HTTP；正式外网访问前必须增加 HTTPS 和更完整的设备身份策略。

## 仍需用户执行

1. 手机和电脑连接同一 Wi-Fi。
2. 在电脑页面扫描配对二维码。
3. 确认手机能看到“AI Center 已连接”。
4. 手机发布一条信息，观察电脑是否在约 1 秒内自动出现。
5. 关闭并重新打开手机页面，确认不要求重新配对。

如果手机无法打开页面，需要用户反馈浏览器错误或截图，用于区分 Windows 防火墙、Wi-Fi 客户端隔离和浏览器兼容问题。
