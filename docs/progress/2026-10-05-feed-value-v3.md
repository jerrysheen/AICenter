# 保存价值 V3 与 Tag 解耦

用户要求：JEV 判断有没有实质保存价值，ContentItem 落库后由现有 AI 打 Tag。
无 Tag 可作为后续补充分类的线索，不是入库质量淘汰依据。

## 已完成

- 默认 `feed-value-v3.0` / shadow；旧 V1 可显式选择，V2 问题与回放冻结为对照。
- 五个 Noul：reading_value 主判断；广告、具体程度、充分程度只诊断；缺失诊断单独读采集状态。不发 readingScope、Tag、topic_relevance、来源名气。
- 主帖、已核验同账号且可追溯回复关系的续帖、必要引用共同评分；普通评论不发模型。显示名同名不恢复正文。
- Connector 传递截断与未展开长文事实。结构化缺失记录对象、关键性、依据；事实先于模型。可独立理解的提示词不被演示视频缺失阻断。
- 校准与 Domain 注入分离；固定模型/问题/输入/样本指纹，改问题或输入不复用旧分数。未校准或失配保持 REVIEW，未取得资格的候选不得 enforce。
- shadow 下 Capture 记录质量状态，ContentItem 继续创建，再走原有翻译/Tag。未实现新 Tag 自动创建或新无 Tag UI。
- 报告只嵌摘要和原问题样本标题，约 21 KB；完整原文/概率单独 JSON，避免旧 13 MB、近千万字符单行 HTML 的编辑器恢复卡顿。
