# 2026-10-03 媒体已读排序与官方发布补齐

## 目标与原因

用户要求媒体文章像 X 一样已读下移，并检查此前约定的宏观官方文章为什么很少。
核对当前 Instance 后，宏观确实只有4篇美联储全文，另有71条BBC/FT摘要。已有17个
静态官方Source包含11个日历和6个官方发布能力，不能把17个日历/政策Source说成17个
媒体全文源。此前仅美联储接入媒体；48小时回看窗口也会漏掉几天前的央行/政府文件。

## 决定与改动

- 媒体仍用 `media-index` ID做翻译、标签与引用；Feed Repository批量关联真实
  Capture/ContentItem，投影 `contentItemId/isRead/createdAt`。页面打开文章通过既有
  ContentItem状态API保存已读，更新媒体列表，清掉设备展示缓存。返回列表后下移，
  服务端分页前先排未读，数据库重开仍保留状态。无需新表或migration。
- Instance登记已有白宫、Federal Register、国务院政策文件库、政府重要会议和央行
  release Source，和美联储一起使用 `existing_adapter`；不把日历自动转换为文章。
  六家官方发布回看720小时，其他媒体缺省仍48小时。Source列表指纹包含回看窗口。
- 正文候选在各来源内部按原有规则排名，来源之间轮流取文，避免科技关键词占满候选批次。
  已选择的较旧文章也加入翻译/标签输入，不受最近120条摘要列表限制；全文翻译先于摘要。
- 中国政府网提取首个TRS编辑正文，排除元数据和重复手机版；央行提取`#zoom`；白宫
  提取WordPress正文。原有出版商提取分支和版本`media-dom-2`保持兼容，不让已有全文失效。
- 五个新增来源在本地经Service显式启用并确认正文用途，运行真实Worker sync/enrich。
  每小时Schedule、32篇成功正文/日、48次正文HTTP/日及各源上限继续生效。
  首轮受限/预算延后保留状态，不提高额度或清空冷却。
