# 社媒默认显示 X 和雪球

2026-10-21 信息流「社媒」只剩雪球，简报里仍有 X。接口上 X 的 for-you 和 following 各有 12 条未读。日志在第一页之后立刻请求 `before=1,9007199254740991,~`。

这条地址不是「未读已被判空」。未读游标以 `0,` 开头，表示这一页有内容，而且最后一条仍是未读。客户端只有在这一页确实装入了条目时才记下这个游标，然后去取一页已读，接在未读下面。未读条数为 0 时不再直接发这支请求：先不带 `before` 再拉一次未读。确认仍没有未读就停住。确认到未读之后，才按原来的方式接已读。

旧的本地记录若平台是 X 或雪球，不再悄悄收成看不出的筛选。社媒频道下面是「全部 / X / 雪球」。没有单平台记录时选中「全部」，X 和雪球一起出现。有单平台记录时，对应芯片是选中的，点「全部」清除。从信源打开 X 或雪球也走这排芯片。全部时，已经装入的两边未读各留一页，雪球不会把 X 挤出第一窗。

`api()` 现在是普通函数，JSON 解析在 `performApi`。测试改为抽出这两个函数，不再查找 `async function api(`。

不新增 migration。当前 schema 仍是 96。下一号是 97。空号仍是 63、79、80、82。不要重建数据库。需要重启 Web，浏览器再加载一次。Worker 不用为这项重启。
