# 2026-10-10 小时报排版 v1

`#report` 的小时报页签改成左右两栏：电脑端左侧约 200 宽的小时竖列，右侧是这一期正文。手机仍用顶部横条，新到旧从左到右。

- 地址支持 `#report?hour=HH` 和 `#report/YYYY-MM-DD?hour=HH`。`hour` 是 0–23 的整数，缺省或非法时不带小时。页内切换用 `history.replaceState` 写回同一地址。请求的小时还没生成时，选最近一期并提示「HH:00 那期还没生成，已显示 hh:00」。
- 连续缺期合成一行，例如「12–16点」。点开显示「12:00–16:00 · 5 期未生成」。命中数来自 `GET /api/v1/reports/reading-hour/index`，查询窗口和简报目录一样，不超过 7 天。这个接口返回 404 时不显示数字，也不逐小时去要。
- 正文标题是「15:00 – 16:00」，旁边是「已处理 a/b · 命中 n」，右侧是「‹ 上一期 / 下一期 ›」。大类标题一页只出现一次。「其他 N 条 ›」默认收起，展开后不再重复同级方向大标题。
- 读取用三行骨架。10 秒仍未返回显示「读取较慢 · 重试」，失败显示「这一期读取失败 · 重试」。命中为 0 时显示「这一小时没有命中条目」。最新一期结束超过 2 小时，页顶显示延迟。
- 当前小时画完后，空闲时预取相邻前后各 1 小时。切到已缓存的小时先立刻画出，再按需后台刷新。
- 手势、按钮和键盘走同一条时间方向。手机横条左滑更早、右滑更新。电脑竖列 ← 和「‹ 上一期」更早，→ 和「下一期 ›」更新。缺期直接跳过。

分类、翻译、JEV、新闻筛选、小时报和日报生成没有改。总览和顶部子页签没有动。

验收：`npm run syntax` 通过。`app.js`、`brief-page.js`、`information-tree.js` 另外做了 `node --check`。`npm test` 共 1019 项：通过 1008，失败 10，跳过 1。这 10 项失败都不在本改动里：分析技能 7 项、信息树策略 1 项、`model-usage` 因当前 Node 22.14 没有 `node:zlib` 的 zstd（按基线不计入）、工作包因本机没有 Cursor CLI。小时报路由、缺期、方向和预取测试都通过。
