# 媒体账号外链正文，以及标注查询不再把 id 放进地址

2026-10-20。BBC World 的帖子通常只有一句话和一个 t.co 短链。详情页只要帖子正文非空就标「正文完整」，站内没有去抓链接里的新闻。

现在只对媒体或官方账号开。作者的名字或账号要和 `config/media.json` 里的出版方、栏目对得上，例如 BBC World 对上 BBC。普通用户转发同一条链接不会抓。`AI_CENTER_X_LINK_ARTICLE` 默认打开，`0` 关闭。每天自动翻译上限是 `AI_CENTER_X_LINK_ARTICLE_DAILY`，默认 8，范围 0 到 48。只有打开详情才会入队，同一篇新闻只翻译一次。

抓取不带 cookies。t.co 只能作为跳转，落地必须是媒体来源允许的域名，并且拒绝私有地址。正文大小有上限。付费墙、拒绝访问或抽不出全文就停下，不把摘要当成全文，也不标「正文完整」。短链展开后，详情里多一个「阅读 BBC 原文」这样的链接。「原帖」仍打开 X。中文正文复用现有的媒体正文抽取和 Gemma 翻译，不覆盖帖子原文的存储；阅读页在译完后显示中文。

标注列表以前用 GET，把信息流里每条 id 都拼进查询串。加载更多会把已翻过的条目留着，查询越来越长，请求头超过上限后出现 HTTP 431，HTTP/2 则报 `ERR_HTTP2_PROTOCOL_ERROR`。现在改为 `POST /api/v1/tagging/query`，每批最多 40 条，批与批之间至少隔 1.5 秒，同一条 60 秒内不重复查。GET 超过 24 个 id 直接拒绝。单条 GET 仍可用。

migration 94 `x_link_articles` 只新增外链正文表。当前 schema 是 94。下一号是 95。空号仍是 63、79、80、82。不要重建数据库。需要同时重启 Web 和 Worker，浏览器再加载一次。
