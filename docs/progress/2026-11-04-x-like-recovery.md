# X 自动点赞挂起恢复

## 现场与结论

旧自动点赞在 10 月 31 日连续三次返回 `unavailable`、空账号后，按安全规则关闭页面开关并挂起。环境开关仍打开不代表会派发点赞。旧 Connector 吞掉浏览器异常，仅留下通用结果，无法从历史 Job 反推这三次究竟是账号壳未就绪、页面变化还是操作超时；不能据此认定账号掉线或按钮无法点击。

本次在 Instance 配置的采集浏览器只读探测：无登录墙，Profile 与账号切换器完整，账号可识别；最新原帖与符合现有自动点赞排名的一条候选均可识别点赞状态。账号与候选身份只保存在 Host 的 `.ai-data/x-like-repair/`，不进入 Core 常量。

实际复核又复现两种瞬时失败：`not_found` 携带 `selector <具体选择器> did not match any element`，旧缺元素判断未匹配包含选择器的新文案；以及导航后 `permission_denied` 携带 `Could not establish connection. Receiving end does not exist.`，内容脚本尚未接上。二者都会被旧代码吞成空账号 `unavailable`。这证明现有链路会误报，不能证明 10 月 31 日每一次失败均为同一根因。

## 变更

- 点赞命令将页面变动依赖收窄到稳定 Profile 区域，避免推文视频等无关变化拒绝整页操作；执行脚本仍同步检查账号、原帖链接、唯一原帖、可见弹窗及按钮状态。
- BrowserSkill 缺元素识别兼容包含具体选择器的错误文案；依赖元素缺失时沿用原有的一次取消收窄机制，让只读脚本判断登录墙或账号壳未就绪。
- 点击前的只读检查遇到页面变化或超时，最多再恢复两次。点击只执行一次，结果未知时仍不重试外部写入；点赞后重开原帖核验保留。
- LikeResult 新增可选封闭 `reason`，区分账号壳未就绪、按钮不可用、页面变化、浏览器超时/连接未就绪/断连/异常。仅上述明确的内容脚本未接上错误可恢复；其他权限错误不重试。旧记录兼容。异常只输出归类，不输出命令、浏览器身份、原始异常；已验证账号在后续操作失败时保留。
- 连续三次不可用的挂起规则不变；新失败提示按原因区分，不再把所有失败写成按钮无法操作。不改评分、候选过滤、配额、不感兴趣开关或历史 Job。

专项最终 75/75 通过，覆盖页面变化和超时的有限恢复、内容脚本启动恢复、真实权限拒绝不重试、新旧缺元素文案、写入不重复、点击后超时和未派发的 settling 读取恢复、重开持久状态、账号变化拒绝、原帖/回复隔离、歧义拒绝、已点赞幂等、挂起和脱敏原因。Contract TypeScript 与改动文件语法校验通过，`git diff --check` 通过。

最初一条旧 HTTP 测试受 Host `.env` 打开自动点赞影响，断言环境开关默认关闭失败；以仅当前测试进程覆盖两个自动互动环境开关后通过，不修改 Host 配置。

安全重载等待当前小时报结束，随后由原启动器重载 Web / Worker，恢复维护期间暂缓的 43 个排队任务及原启用调度。数据库、迁移、浏览器 Profile 和历史任务均保留。真实点赞与恢复结果见下文验收补记。

通过现有 HTTP 手动点赞命令和注册 Worker handler，对按原自动规则选中的方向分 1.0 候选只执行一次真实点赞。Job 返回 `liked`，内部重开原帖确认成功；后续独立复核发现上述两类瞬时错误，因此仍保留挂起继续修复。补修后连续五次只读重开均返回同账号 `already-liked`，没有再点击或取消点赞。

全仓 `node --test` 本轮 2167 项中 2147 通过、20 失败；包括旧 HTTP 测试的 Host 环境默认值断言及其他模块失败，不视作全仓发布通过。专项测试使用进程内隔离开关，不改生产 `.env`。

## 最终真实验收与恢复

后续自动候选依旧经 X Focus Service 原排名、准入、推广/敏感排除和配额筛选，交给注册 `feed.x.like` Worker 执行。发现 Worker 同期事件循环最长阻塞约 11 秒，自动任务的 10 秒浏览器截止触发，返回带已验证账号的 `unconfirmed / browser-timeout`。独立重开该帖确认同账号已点赞，保留原 Job 的未确认历史，不伪造执行结果。

最终将点赞命令时限调整为 30 秒，读取恢复共用在点击前检查与点击后核验；只有只读操作可在明确页面变化、超时、内容脚本未就绪、或明确「上一操作仍在收尾、此次未派发」时额外恢复两次。写入始终只发一次。真实权限拒绝仍不重试。

修复期间的一次重载被超过 10 分钟的只读媒体同步阻住，原维护脚本按时退出并恢复调度，未强制重启。随后确认该同步尚有一次尝试额度，通过原启动器重载，由现有租约机制重新领取为第 2/2 次，已保存内容保留。最终核验修复重载时等待所有运行任务完成，恢复 52 个暂缓队列任务。

最终经原 HTTP 开关恢复自动点赞，确认 `environmentOn=true / pageOn=true / stopped=false`、提示为空。全部 50 条原启用调度恢复，健康接口 200。本次一次手动验证与一次自动点赞均独立重开确认已点赞；自动任务原超时历史保持原样。每日 8 次、每小时 2 次、0.8 门槛和 15 分钟最小间隔均未修改。再次尝试派发返回原有 `limit`，遵守间隔，不绕过限制继续点赞。
