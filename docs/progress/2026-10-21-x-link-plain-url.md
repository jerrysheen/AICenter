# 媒体短链跟到原文，纯文本链接不再标正文完整

2026-10-21。#185 上线后，BBC World 带链接的帖子打开仍是「仅帖文」或「正文完整」，没有中文正文，也没有「阅读 BBC 原文」。

公开时间线里，`2110738045825593390` 的正文是 `https://t.co/MVj4mMZ36G`，展开后是 `https://bbc.in/4yWhqSC`。实测不带 Cookie 的跳转是 t.co → bbc.in → trib.al → `www.bbc.com`。`bbc.in` 和 `trib.al` 都不在媒体域名白名单里，抓取在短链上停下，出版方标签也写不出来，所以页面留在「仅帖文」，没有原文入口。

`2111969849165377774` 在 X 上显示成纯文本 `bbc.in/47XDz70`（时间线用的是链接的显示文字，不是 `https://`）。抽取只认带协议的地址，页面认为没有外链，沿用「正文完整」，也不会入队。

现在这三跳都只跟随，落地仍必须是已登记的媒体域名。正文里的 `bbc.in/路径` 这种纯文本也算外链。媒体帖一入队就写上「阅读 BBC 原文」，译完才标「正文完整」。付费墙和抓不到全文仍不标「正文完整」。普通用户的外链不抓。每天翻译上限仍是 8。

已经在库里的老帖用 `node scripts/backfill-x-link-articles.mjs --dry-run` 看会补哪些，再去掉 `--dry-run`。默认看最近 14 天，只排当天还剩的名额。短链被拒、已经失败 3 次的会重新排队。指定某一条：`--tweet 2110738045825593390`。名额用完的下一天再跑一次。打开详情也会入队，同样受每天 8 篇限制。

没有视频的帖子不再请求 `/api/v1/x-videos/<id>/article`。信息流后台刷新不再把已保留的整表标注一次查完；作者列表打开时不再插入这批请求，作者列表请求优先发出。

不新增 migration。当前 schema 仍是 94。下一号是 95。空号仍是 63、79、80、82。不要重建数据库。需要同时重启 Web 和 Worker，浏览器再加载一次。
