# 信息流搜索改走全文索引

2026-10-21。#189 上线后，搜「Cranmer」能找到 Miles Cranmer 的帖子，但本机每次要 3.8 到 4.5 秒。搜索把标题、摘要、作者和正文前 4000 字拼在一起做 `LIKE`，每一行还要再查可见性。

现在三个字及以上走 SQLite FTS5 trigram 全文索引，忽略大小写。两个字 trigram 对不上，只查标题、摘要和作者，不扫正文。一个字不查。页面上少于两个字不发请求；发出新的搜索时取消上一个请求，搜索结果也不进 8 秒缓存。

migration 96 只建空的 `content_item_fts` 和进度表 `feed_search_index_cursor`，不在迁移里灌入已有帖子。Web 和 Worker 启动并开始接请求之后，每次 40 条写入索引，写完一批就让出主线程。新保存的帖子当时就写入索引，不用等这一轮走完。当前 schema 是 96。下一号是 97。95 留给尚未合并的工作，空号是 63、79、80、82、95。不要重建数据库。

搜索结果里的 `subscriptionId` 以前写死成空字符串。补录会把帖子挂到 `x:home:following`，但这个来源以前可能没有订阅行，接口也就看不出挂上了没有。现在补录会补上这条订阅，搜索按帖子所在来源返回订阅 id。已经挂在关注信息流、并且已有订阅时，重启后搜索就会带上 id，不必再跑补录。标题仍是「以下是演讲全文：」，不另建整理任务。

需要同时重启 Web 和 Worker，浏览器再加载一次。索引在后台补，不挡住领任务。这一集不用重新整理。若重启后这条帖子的 `subscriptionId` 仍是空的，说明它还没挂到关注信息流，再执行：`node scripts/repair-x-video-feed.mjs --tweet 2111105654211608847`。可以先加 `--dry-run`。
