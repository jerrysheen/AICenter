# 昨天的位置不再挡住今天的小时报

## 目标

停在昨天（例如 `#report/2026-11-01?hour=23`）时，期数菜单只有这一天的小时和「更早 / 前一天」，「下一期」在 23:00 停住，进不了今天已经生成的类目小时。总览小时报区块已经是今天 15:00–16:00，点「更多」却打开 `#report/2026-11-01?hour=15`。

## 决定

地址只写了钟点、没有日期时，在今天已经有刊期的情况下，只在今天里对这个钟点。今天没有这一小时，仍在今天里退到最近的更早一期。今天完全没有刊期时，维持原来的「当前这一天」选择，避免把旧测试和清晨没有新刊的情况改到更早的同一钟点。

查看日不是今天、而且今天有更晚的刊期时，「下一期」和菜单里的「今天 ›」都去今天最新有内容的一小时。有阅读索引时看 `selected`，没有索引时看刊期是否有条目；都没有内容时才用今天最新一份。已经在今天时，「今天 ›」隐藏，「下一期」仍只在当天里走，到最新一期就停。

总览「更多」用区块里正在显示、并且有条目的那一小时，不拿刊期列表里更靠前、还没有条目的一份。这一小时不是今天时，地址写成 `#report/日期?hour=`。

## 改动

- `apps/web/public/information-tree.js`：无日期的钟点优先今天；非今天时提供「今天 ›」，当天最后一小时的「下一期」可以跨到今天最新有内容的一期。
- `apps/web/public/home-timeline.js`：`reportHourHref` 在非今天时带上日期；`homeHourMoreStart` 选择总览正在看的那一小时。
- `apps/web/public/app.js`：总览「小时报 → 更多」走这个起点。
- `apps/web/public/styles.css`：期数菜单里的「今天 ›」和「昨天 ›」同一套样式。窄屏菜单里仍能看见。
