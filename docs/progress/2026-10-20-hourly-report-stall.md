# 小时报主线程卡顿

2026-10-20。模型执行本身是 6–11 分钟。Worker 主线程被三件事堵住：X 同步结束时整批入库、三份快照大约每 37 秒全量重写、同一秒多份材料准备时对整篇 JSON 做哈希和同步写库。小时报又在单队列里串行调模型，阅读分类批次也串行，截断失败还被缓存，旧时段补跑会用同一批材料反复入队。

`market.holdings.snapshot`、`source.static-signal-board.snapshot`、`feed.lists.snapshot` 改为每 5 分钟。报价（代码、最新价、前收）、走势末点、看板即将发生和已发布条目、信息流条目 id 与时间没变时，不重写对应快照。官方看板仍同步作者和不足 80 字的正文。`market.boards.snapshot` 等其余快照仍是 1 分钟。

X 入库和未展开正文结算每 8 条让出一次主线程。x-focus 每一批打分之后、关键词回写每 8 条同样让出。材料哈希先让出，再按 32KB 分块计算，结果与原来的同步哈希相同。

小时报 tag 组最多 3 路同时调用模型。阅读分类批次最多 3 路，单次超时 60 秒；超时仍算非配额错误，换下一把密钥再试一次。最新小时 priority ≥ 0，先占前景位。旧时段补跑 priority 为负，另占一位，不占用最新小时的位置。

`gemini-3.1-flash-lite` 截断时，该组改用 `gemini-3.5-flash-lite`，输出上限 8192。仍然截断且组内多于一条，就对半再跑。截断失败不写入分析阶段的失败缓存，下一次会重新调用模型。

补跑除了比对节点 id，还比对 `sourceId` 与 `sourceVersion`。已发布版本覆盖这批材料就不再入队。同一次尝试已经覆盖同样的材料印记，也不再入队。材料版本变了仍会补跑一次。

`AI_CENTER_MAIN_THREAD_WATCHDOG=1` 才启动看门狗，默认关闭。工作线程每秒 ping。主线程超过 10 秒没有回应，记下 ISO 时间和当时正在跑的任务。Worker 的 `main` 给标准输出和标准错误加上时间戳；任务执行期间再带任务 id。

不新增 migration。当前 schema 仍是 91。下一号仍是 92。空号仍是 63、79、80、82。不要重建数据库。需要同时重启 Web 和 Worker。
