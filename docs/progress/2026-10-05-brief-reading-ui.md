# 简报阅读界面

后续已恢复真实摘选并加载运行服务，且按用户要求完成首屏阅读减法。本记录保留初次UI轮次状态，当前结果见 `2026-10-05-brief-data-recovery-and-reading.md`。

## 目标

按用户提供的简报设计、响应式补充和独立原型，局部改造现有日报页面。原型的文章、主题、时段、数量、模拟更新不作为生产事实，也不整页覆盖 App 外壳。

## 决定与改动

- 保留 `report` 深链接，将显示名称改为「简报」，共用小时更新 / 日报精选两种视图。设备身份隔离地记住视图；历史日期深链接仍可进入相应日报。
- 新组件 `apps/web/public/brief-page.js` 负责共享信息行、日期、已读/收藏、查询、版本提示与证据面板。没有可靠主题数据就按现有顺序阅读，不按关键词或来源猜主题、不增加模型调用。小时组先显示4条；日报全量读取 `informationItems`，超过20条可展开，不使用旧概览前8项冒充全部。
- 增加 Report Contract → Service → Repository 的只读小时版本清单和指定成稿统计窗口读取。每60秒检查元数据，不循环加载整日原文；首读分批GET不可变完整快照，规避搜索分页遗漏。清单保留旧有效发布结果与新失败/进行中状态，排除非完整小时的日报边界快照。新冻结记录补存window；不改已执行迁移或旧快照。
- 同句子/同证据版本在换快照后沿用阅读状态；正文或材料版本更正使用新显示身份。设备状态仅保存签名，不保存正文，退出/换身份清理，晚到响应不能回填另一会话。
- 更新到达时保留筛选、展开与冻结来源，阅读中只提示；同版本不反复提醒。修订日报主动切换；普通检查只GET。弹层开着时补偿提示插入的阅读锚点，关闭来源后恢复原位置。已有资料可进入现有文章路由并返回。
- 样式限定 `.brief-*` 与日报根节点；不改全局导航600/840/1200px规则，1440px以上才显示236px辅助栏。手机来源底部面板、中等宽度宿主弹层、桌面右面板；主要触控操作44px高。生成、重试、范围和追踪配置移至正文后的折叠管理区，权限仍按本机身份。
- 静态资源注册新组件。当前工作区并行加入的硬件报价页面已有App import，补齐对应静态资源注册与旧Web缺模块时的动态加载兼容以保障App加载；全仓检查定位到X/雪球分支误带入的未定义TrendForce options，移除两处跨来源条件。保留工作区其余既有改动。
- 小时迁移回归fixture只撤销38/39记录，不再删除其他独立新迁移记录后误重复建表；不触及真实数据库。

## 验证

- 最终 `npm run check`：语法、Source/Harness、Contract类型、架构、Harmony与754/754测试全部通过。中途一次调度测试因Windows临时数据库清理EBUSY失败，单独8/8及完整重跑均通过；未修改调度生产逻辑。
- `scripts/verify-brief-ui.mjs`：真实App静态页＋合成API、无头Chromium；320/375/390/699/700/768/1024/1199/1200/1366/1440/1920，12个宽度×2视图，无横向溢出/JavaScript异常；主要操作≥44px，底栏/辅助栏断点符合宿主规则。
- 验证小时展开、12条完整日报（超过兼容8条）、多段同材料去重、支持段落与上下文、Escape及滚动恢复、来源面板中接收更新提示、相同版本不重复提示、换快照保留已读/收藏、离线恢复、日报修订、旧日期晚到响应、资料库文章往返、仅GET更新、授权失效清理。
- 既有 `scripts/verify-uiux-reading.mjs` 回归通过：信息流/文章返回、导航轮换、Ask与量化状态、资产图表/隐私、页面布局和合成软键盘等。
- 截图、合成结果和检查日志留在忽略的 `.ai-data/brief-ui-probe/` 与 `.ai-data/brief-ui-check.log`，不提交真实材料、Host路径或生产诊断导出。

## 运行与遗留

- 不更改采集/筛选规则、生成频率、模型预算、设备权限或已有持久内容。
- 新读取接口和静态模块注册需要Web进程加载；新冻结窗口字段随Worker加载。本轮结束时小时提炼仍有running/queued任务，未强杀Worker或请求启动器重载。App使用动态组件加载，旧Web尚未注册新文件时保留既有日报/小时阅读，不因模块404卡住授权启动；该兼容路径也经过合成浏览器测试。新界面待安全空闲后的正常服务重载生效。
- 无头合成浏览器通过不等于iOS/Android/鸿蒙真机、软键盘、安全区和实际生成语义已验收；整体0.2.0发布门槛保持原状态。
