# 常用接口响应与 Web 阻塞修复

## 观测

本机读取接口连续三轮抽样，保留 Web/Worker 正常任务运行。股票看板约 10–23ms，单股报价约 26–307ms，首次历史 K 线约 160–351ms；媒体列表稳定约 1.6–1.7 秒、播客列表约 0.49–0.56 秒。媒体、播客和历史小时报并发时，健康检查曾等到 2540ms，说明同步投影拖住了其他 HTTP 请求。

原始探针、接口时序与临时重载记录只保存于 Host 的 `.ai-data/api-perf-*`，不提交个人资产、正文、数据库或登录信息。

## 修复

- 严格准入的媒体列表通过 Feed Repository 获得已通过的身份集合，交给 Media Repository 做分页与分类计数，不再先读取并解析最多一万条媒体索引再生成排除列表。空准入集合返回空列表，未评分、隐藏内容不能旁路；频道、来源筛选、顺序、游标和计数保持原语义。
- 媒体 HTTP 投影复用现有后台读取线程，线程构造同一 Media Service / Repository，注入相同 Instance 目录和准入模式。媒体响应不做 TTL 缓存，避免下一次读取看不到已读/隐藏变化。刷新仍派发原有注册 Job，无外部抓取进入 Web 请求。
- 读取线程异常退出后清理等待者并快速失败；后续请求不能继续发送到已退出线程。Promise 清理回调消费拒绝，避免额外的未处理拒绝。
- 小时报批量读取原文概要/来源名称时，明确使用既有内容 ID 主键索引，避免 SQLite 为大 IN 列表选择工作区范围扫描。同一历史小时底层读取约 300ms → 1–2ms，不改内容和来源归属。
- 显式时区格式化器按时区复用，最多 32 个；隐式系统时区不缓存。保留 DST、无效时区校验及原有时区换算。已 ready 的播客无需计算下次整理时间；未知时间不再把 null 当作 Unix epoch。
- 股票看板、K 线与播客列表启用已有的协商 gzip 响应，保留 JSON 结构、状态码和价格来源时间。
- 发现一条 GPU Economy 抓取已挂起超过 17 分钟。CCIR / Bargo / GPU Economy 的每次 HTTP 与正文读取共用独立 20 秒截止；即使 Transport 忽略 AbortSignal，也会释放调用者。固定 GPU Job 传递 Worker 取消信号，并在保存前复核，取消不能迟到落库。通过 Runtime 维护入口终止这次已挂起的只读抓取，已有报价快照保留。

## 验证与限制

- 回归覆盖准入集合分页、空集合、重复身份、跨 workspace 身份查询、主键查询计划、后台线程与同步投影一致、已读/隐藏立即生效、线程退出、DST 与取消失效的 Transport / Body。
- 专项回归通过；全仓 `node --test` 仍有其他失败，不视作整体发布通过。标准 `npm run check` 仍受 Windows 超长 syntax 命令限制；逐项等效执行语法、Contract 类型检查通过，架构检查仍报告当前仓库既有越层依赖。Harmony 校验通过。
- 不新增 migration、不重写迁移，不修改准入阈值、个人持仓或浏览器身份；保留本轮之前暂存的自动部署改动。

## 本机生效复测

Web / Worker 已经由原启动器安全重载，恢复维护期间暂缓的任务；确认 50 条调度启用，健康接口返回 200。22 类常用接口各读三轮，共 66 次均返回 200。

| 读取 | 修复前 | 修复后（三轮） |
| --- | --- | --- |
| 媒体列表 | 1.6–1.7 秒 | 902–940ms |
| 播客列表 | 486–558ms | 145–194ms |
| 股票看板 | 约 10–23ms | 16–36ms |
| 历史小时报 | 批量来源查询会扫描工作区 | 单独请求 16–18ms |

股票读取本来较快，此轮重点减少大响应传输并隔离其他接口阻塞；CN 看板 JSON 119523 字节经 gzip 为 24548 字节。AAPL 单股首次上游读取 956ms，后续缓存读取 2–11ms，外部冷读取仍存在波动。

媒体、播客与历史小时报同时请求时，最新健康探针最高 208ms（修复前 2540ms），其余探针 13–20ms；该轮媒体和小时报均约 1.06 秒，说明后台读取队列仍可能增加等待，不能把单独请求时延视为并发保证。

最终专项回归 139/139 通过。全仓测试 2157 项中 2131 通过、26 失败，未达到全仓发布验收线；语法、Contract 类型和 Harmony 校验通过，标准检查的 Windows 命令长度与既有架构违规仍待另外处理。
