# 连接、配对与安全

## 为什么使用二维码

二维码用于避免用户手工输入本机 IP、端口和配对码。它只是连接信息的载体，不代表每次打开应用都要重新登录。

局域网二维码内容包含：

- 当前服务器局域网地址。
- 一次性配对码。
- 配对码过期时间。
- 协议版本。

二维码不得包含长期设备 token。

配置公网入口后，公网二维码不再使用六位配对码，而是使用 256 bit 一次性随机凭证。六位码只保留给局域网手工配对，
避免公网暴力枚举。公网二维码仍然不包含长期设备 token。

当前配对接口生成 HTTP 和 `aicenter://pair` 两种载体。局域网载体携带六位码；公网载体携带高熵一次性凭证。
两者都只用于换取设备授权。

## 三种不同的“持续时间”

### 配对码

- 局域网六位码默认有效期：10 分钟。
- 配置公网地址后，一次性公网凭证默认有效期：2 分钟。
- 使用一次后立即失效。
- 过期只影响新设备配对，不影响已经连接的手机。
- 非本机配对请求限制为同一来源 5 分钟最多 10 次。

### 设备授权

- 服务端设备授权在撤销前有效；HTTPS Cookie 当前有效期为 180 天。
- 手机安全保存设备 token。
- 服务端只保存 token 哈希。
- 用户主动撤销、重置服务端身份或清空手机应用数据时才需要重新配对。
- 手机浏览器通过同源的 HttpOnly Cookie 保存授权，页面脚本不能读取长期 token。

后续如果需要更严格的策略，可以增加“连续 180 天未使用自动失效”，但第一版不启用。

### 实时连接

- 页面打开时维持一条 SSE 长连接。
- Wi-Fi 切换、锁屏或系统回收连接后，客户端自动重连。
- 自动重连不等于重新配对；设备 token 仍然有效。

## 什么时候需要重新扫码

只有以下情况需要：

1. 用户在服务器上撤销了这台手机。
2. 手机清除了 AI Center 应用数据。
3. 服务端身份密钥被重置。
4. 使用手机浏览器且服务器 IP 发生变化，导致原地址下的浏览器凭证无法继续使用。

当前第一版鸿蒙薄壳用 Preferences 保存服务器地址，用 ArkWeb 的 HttpOnly Cookie 保存设备授权。因此关闭并重新打开应用不需要扫码；但局域网 IP 发生变化时，Cookie 的主机范围也会变化，当前仍需要重新配对。后续把 token 放入系统关键资产服务并由原生层重新注入 Cookie 后，才能做到只更新地址而不重新配对。

本地灵感不依赖配对或在线状态。系统分享使用原生详情页（不加载远端 ArkWeb）：用户确认后先写入有界本地 RDB Outbox。主应用原生输入页同样先写本机。只有主 ArkWeb 已建立有效设备会话后，才通过 `AICenterShell` 读取待同步记录并调用既有 `POST /api/v1/notes`。原生层不读取、复制或持久化 HttpOnly Cookie；分享内容不放进 URL。撤销授权后，本地记录继续保留为待同步；重新配对成功后以同一个 `clientMutationId` 重试。不能为分享入口放宽 API 鉴权。

薄壳每次启动先读取已保存地址，并对 `/api/v1/health` 做短超时探活（局域网 2.5 秒、公网 HTTPS 5 秒）。探活失败立即报错，但**不删除**已保存地址和 Cookie；电脑恢复后点重新连接即可。探活成功后才打开业务页，信息流加载可以较慢，不再当作“登录失败”。只有用户主动退出、更换服务器或扫描新码时才清除本地地址。

## 网络范围

- 默认模式只支持电脑和手机位于同一局域网。
- 服务监听局域网接口，但所有业务 API 都要求设备授权。
- 不配置路由器端口转发。
- 不将服务直接暴露到公网。
- API 不开放跨域访问；配对、发布和实时连接都从同一页面来源发起。

可选公网模式使用稳定 HTTPS 域名和出站 Cloudflare Tunnel，不开放路由器入站端口。公网请求永远不能获得本机管理员身份，
详细边界和部署步骤见 `docs/public-access-security.md`。

## 配对流程

```text
桌面生成短期配对码
        |
手机扫描二维码
        |
POST /api/v1/pair
        |
服务校验未过期且未使用
        |
签发设备 token，配对码失效
        |
手机保存服务器地址和 token
        |
后续请求直接携带 token
```
