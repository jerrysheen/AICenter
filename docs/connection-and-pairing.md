# 连接、配对与安全

## 为什么使用二维码

二维码用于避免用户手工输入本机 IP、端口和配对码。它只是连接信息的载体，不代表每次打开应用都要重新登录。

二维码内容包含：

- 当前服务器局域网地址。
- 一次性配对码。
- 配对码过期时间。
- 协议版本。

二维码不得包含长期设备 token。

## 三种不同的“持续时间”

### 配对码

- 默认有效期：10 分钟。
- 使用一次后立即失效。
- 过期只影响新设备配对，不影响已经连接的手机。

### 设备授权

- 默认长期有效，没有日常超时。
- 手机安全保存设备 token。
- 服务端只保存 token 哈希。
- 用户主动撤销、重置服务端身份或清空手机应用数据时才需要重新配对。
- 手机浏览器通过同源的 HttpOnly Cookie 保存授权，页面脚本不能读取长期 token。

后续如果需要更严格的策略，可以增加“连续 180 天未使用自动失效”，但第一版不启用。

### 实时连接

- 页面打开时维持一条 SSE 长连接。
- Wi-Fi 切换、锁屏或系统回收连接后，客户端自动重连。
- 自动重连不等于重新配对；设备 token 仍然有效。

## 什么时候需要重新扫码

只有以下情况需要：

1. 用户在服务器上撤销了这台手机。
2. 手机清除了 AI Center 应用数据。
3. 服务端身份密钥被重置。
4. 使用手机浏览器且服务器 IP 发生变化，导致原地址下的浏览器凭证无法继续使用。

鸿蒙薄壳将设备 token 与服务器地址分开保存。局域网 IP 变化时，只更新服务器地址即可继续使用原授权；如果手机浏览器直接访问，则可能需要重新扫码。

## 第一版网络范围

- 只支持电脑和手机位于同一局域网。
- 服务监听局域网接口，但所有业务 API 都要求设备授权。
- 不配置路由器端口转发。
- 不将服务直接暴露到公网。
- API 不开放跨域访问；配对、发布和实时连接都从同一页面来源发起。

外网访问、HTTPS、私有网络和推送通知在本地闭环通过后另行设计。

## 配对流程

```text
桌面生成短期配对码
        |
手机扫描二维码
        |
POST /api/v1/pair
        |
服务校验未过期且未使用
        |
签发设备 token，配对码失效
        |
手机保存服务器地址和 token
        |
后续请求直接携带 token
```
