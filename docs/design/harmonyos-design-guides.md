## 0. 如何使用这份规范

这不是一份“照抄鸿蒙外观”的样式清单，而是一份跨设计、开发和验收的共同契约。

- **必须**：上架标准、无障碍和交互安全底线，不满足不得交付。
- **应当**：AI Hub 默认设计决策；偏离时需要在设计稿或变更记录中说明原因。
- **可以**：依业务场景选择，不要求所有端完全一致。
- **官方 Token**：直接继承 HarmonyOS 语义及深浅色映射。
- **产品 Token**：AI Hub 在官方语义上建立的别名，不在业务页面直接写色值、字号或圆角。

多端通用的含义是：**任务、信息语义、操作结果一致；布局、导航密度和输入方式随设备变化。** 不追求把手机界面等比放大到电脑，也不为每个设备复制一套互不相干的页面。

### 0.1 交付物结构

每个新增页面或功能至少包含：

1. `Compact / Medium / Expanded` 三个宽度状态的布局说明。
2. Light / Dark 两套 Token 映射，不单独手填深色值。
3. 鼠标、键盘、触屏的状态与焦点顺序。
4. 页面进入、退出、加载、成功、失败和空状态的动效或静态反馈。
5. 大字体、RTL、安全区、横竖屏和自由窗口的验收结果。

## 1. 一页式设计决策

| 主题 | AI Hub 默认决策 | 禁止事项 |
|---|---|---|
| 视觉基调 | 内容优先、低噪声、清晰层级；蓝色只承担品牌与关键交互 | 大面积高饱和蓝、用颜色代替全部文字说明 |
| 排版 | HarmonyOS Sans；五类文字角色；正文优先 14–16vp，支持系统大字体 | 页面内随意新增字号、固定高度截断文字 |
| 间距 | 4vp 原子网格，常用 8/12/16/24/32/40 | 5、7、13 等无语义散值 |
| 圆角 | 小元素 8vp、卡片 16vp、按钮 20vp、弹层 32vp；电脑端适当收敛 | 同层组件混用多个圆角、层级越高圆角反而越小 |
| 色彩 | 语义 Token 驱动；正文对比度至少 4.5:1；图标/大标题至少 3:1 | 在页面代码中直接写十六进制色值、只靠红绿区分数据 |
| 导航 | `<600vp` 底部页签或单栏；`600–839vp` 视任务采用双栏；`≥840vp` 侧边导航 | 电脑端继续使用被拉宽的手机底栏 |
| 动效 | 状态变化有因果、操作按下即反馈、优先系统转场和共享元素 | 装饰性循环动画、单帧硬切、所有元素同时飞入 |
| 多端 | 共享信息架构与语义组件，按窗口能力渐进增强 | 用设备型号判断布局、为每端复制业务逻辑 |
| 无障碍 | 40×40vp 必须、48×48vp 推荐；支持键盘焦点、减弱动效和大字体 | 颜色作为唯一提示、焦点不可见、禁用系统缩放 |

## 2. 排版系统

### 2.1 字体角色

业务页面只允许使用下列语义角色。字号使用 `fp`，容器与间距使用 `vp`。

| 产品 Token | Compact（手机/折叠窄态） | Expanded（平板横屏/电脑） | 推荐行高 | 用途 |
|---|---:|---:|---:|---|
| `type.display` | 38fp / Light | 36fp / Light | 1.15–1.25 | 关键数字、数据总览，不用于普通页标题 |
| `type.title.l` | 30fp / Bold | 28fp / Bold | 1.25–1.35 | 一级页面标题 |
| `type.title.m` | 24fp / Bold | 22fp / Bold | 1.3–1.4 | 模块标题、弹窗标题 |
| `type.title.s` | 20fp / Bold | 18fp / Bold | 1.35–1.45 | 卡片标题 |
| `type.subtitle` | 16fp / Medium | 14–16fp / Medium | 1.4–1.5 | 列表主文案、分组标题 |
| `type.body` | 14–16fp / Regular | 14fp / Regular | 1.5–1.65 | 正文、表格正文、说明 |
| `type.caption` | 12fp / Medium | 12fp / Medium | 1.4–1.5 | 标签、辅助说明、时间戳 |

规则：

- **必须**支持系统字体缩放；核心操作不可因字体放大而消失或被遮挡。
- 金额、涨跌幅、代码和需要纵向对齐的数据，使用支持等宽数字的样式；不要为了对齐改用图片文字。
- 一行标题应尽量短；长正文建议每行约 45–75 个中文字符等效宽度，超宽窗口限制阅读列宽。
- 中文正文默认左对齐；只有排版引擎能正确处理标点和字间距时才使用两端对齐。
- 英文短 UI 文案不得断词；国际化布局按官网建议预留膨胀空间。
- 文字层级优先靠语义角色和留白表达，不同时叠加字号、字重、颜色三种强调。

### 2.2 页面排版模板

一个标准业务页按以下顺序组织：

1. 标题栏：页面身份、返回关系、最多 1 个主操作，其余进入“更多”。
2. 摘要区：关键指标或当前状态；无关键摘要时省略，不造空卡片。
3. 主内容区：以 8vp 栅格对齐，模块间距大于模块内间距。
4. 辅助信息区：解释、数据来源、更新时间、风险提示。
5. 持续操作区：仅在高频或流程型页面使用，且避让安全区与输入法。

## 3. 色彩系统

### 3.1 产品语义层

业务组件引用产品 Token，产品 Token 再映射到 HarmonyOS Token。这样可以统一切换主题、深色模式和高对比度模式。

| 产品 Token | HarmonyOS 映射 | 使用规则 |
|---|---|---|
| `color.action.primary` | `brand` | 主按钮、选中、可交互链接；一屏不宜出现多个竞争焦点 |
| `color.text.primary` | `font_primary` | 标题和主要正文 |
| `color.text.secondary` | `font_secondary` | 说明、次要指标 |
| `color.text.tertiary` | `font_tertiary` | 占位、辅助元数据；小字号仍需验对比度 |
| `color.surface.canvas` | 产品主题映射 | 页面画布；浅色建议取白/雪域灰体系，深色取近黑体系 |
| `color.surface.card` | `comp_background_primary` | 卡片与主要内容容器 |
| `color.surface.subtle` | `comp_background_tertiary` | 轻量分组、输入背景，不能代替分层结构 |
| `color.border` | `comp_divider` | 分割线和边框，能靠间距分组时优先不用线 |
| `color.state.hover` | `interactive_hover` | 鼠标悬停，不在纯触屏端保留悬停逻辑 |
| `color.state.pressed` | `interactive_pressed` | 按下即时反馈 |
| `color.state.focus` | `interactive_focus` | 键盘/遥控焦点，必须清晰可见 |
| `color.status.danger` | `warning` | 不可逆或高风险操作 |
| `color.status.notice` | `alert` | 需要注意但可继续的状态 |
| `color.status.success` | `confirm` | 已完成、已确认 |

### 3.2 金融数据色

金融数据色与系统状态色分离：

- 建立 `data.positive / data.negative / data.neutral`，不要复用 `warning / confirm`。
- 涨跌方向必须随市场和地区配置：中国内地市场通常红涨绿跌，国际市场常见绿涨红跌。
- 颜色之外同时提供 `+ / −`、箭头、标签或形状，保证色觉异常用户可判断方向。
- K 线、折线和面积图在 Light / Dark 下分别验收；网格线不得抢过数据线。
- 大面积图表颜色降低饱和度，关键点、选中态和交易操作才使用高对比强调色。

### 3.3 深色模式与沉浸光感

- 深浅模式使用同一 Token 名，不在组件内部判断后写两套颜色。
- 官网色彩页中 `background_primary` 的 Dark 表值与正文对“深色基础背景为黑”的描述存在语义差异；AI Hub 不直接引用该原始值作为页面画布，统一通过 `color.surface.canvas` 解析。
- 沉浸光感只用于标题栏、底部页签、工具栏、菜单、弹窗等具有明确空间层级的区域，不铺满正文卡片。
- API 26 及以上优先使用系统材质，让系统随深浅模式、设备算力和用户设置自适应；低版本或低算力设备降级为不透明语义背景、边框和轻阴影。
- 材质上的文字、图标仍需逐帧满足对比度；背景复杂时增加遮罩或改用更厚材质。

## 4. 布局与多端响应

### 4.1 统一断点

断点以**当前窗口宽度**判断，不以设备名称或物理分辨率判断。

| 状态 | 窗口宽度 | 栅格 | 页面结构 | 导航 |
|---|---:|---:|---|---|
| Compact | `<600vp` | 4 列 | 单列；详情覆盖列表 | 底部页签或顶部轻导航 |
| Medium | `600–839vp` | 8 列 | 单列增强或主次双栏 | 侧边页签/紧凑侧栏，按任务复杂度选择 |
| Expanded | `≥840vp` | 12 列 | 主次分栏、并排上下文；内容设置最大宽度 | 可展开侧边导航栏 |

默认边距：Compact 16vp、Medium 24vp、Expanded 32–40vp；gutter 不大于 margin。超宽窗口内容区不无限拉伸，最大宽度遵循官网 2220vp 上限，阅读型内容应采用更窄的产品级最大宽度。

### 4.2 AI Hub 外壳响应规则

| 元素 | Compact | Medium | Expanded |
|---|---|---|---|
| 全局导航 | 3–5 个高频入口放底部，其余进入“更多” | 紧凑侧栏或底栏 | 左侧导航栏，可展示二级入口与状态 |
| 列表—详情 | 点击进入详情页 | 宽度足够时双栏，否则仍单栏 | 默认双栏，允许调整比例 |
| 搜索 | 独立搜索页或全宽搜索框 | 标题区内展开 | 可常驻标题栏，并保留快捷键入口 |
| 筛选 | 底部半模态 | 半模态或侧面板 | 常驻筛选栏/侧面板；复杂条件可弹窗 |
| 主操作 | 底部安全区上方或标题栏 | 随内容或标题栏 | 标题栏/工具栏，不把按钮拉满整行 |
| 表格 | 卡片化关键字段，次要列进入详情 | 优先列 + 横向滚动 | 完整列、排序、列宽与键盘操作 |
| 图表 | 单图聚焦，详情按需展开 | 图表与指标组合 | 多图对比，但保持同一时间轴与图例规则 |

### 4.3 设备差异

- **折叠屏**：展开/折叠时保留任务、滚动位置和输入内容；避让转轴；悬停态才使用上下分区。
- **平板**：兼容横竖屏、分屏和自由窗口；不要假设始终全屏。
- **电脑**：必须提供 hover、右键、滚轮、键盘焦点、快捷键和窗口缩放；触屏电脑仍满足触控热区。
- **智慧屏**：远距离观看、遥控焦点和更大字号是独立设计条件，不直接复用电脑页。
- **穿戴**：只保留可在短时、单手完成的核心任务，不把完整手机功能塞进圆屏。
- **座舱**：驾驶安全优先，禁止把长按、拖拽等高注意力操作作为关键路径。

## 5. 动效系统

### 5.1 动效的职责

每个动效必须至少承担一种职责：反馈操作、解释空间关系、维持对象连续性、表达进度或聚焦注意。无法说明职责的动效应删除。

| 产品 Token | 建议时长 | 场景 |
|---|---:|---|
| `motion.instant` | 80–120ms | 颜色、透明度、按压反馈 |
| `motion.quick` | 150–200ms | 小控件、菜单项、开关 |
| `motion.standard` | 200–250ms | 卡片展开、局部面板、筛选切换 |
| `motion.page.compact` | 250–300ms | 手机全屏页面转场 |
| `motion.page.medium` | 280–320ms | 折叠展开态、平板转场 |
| `motion.page.expanded` | 300–350ms | 电脑/大屏的大范围转场 |

全屏转场同时满足官网 UX 下限：8.5 英寸以下不少于 200ms，8.5–12 英寸不少于 250ms，12 英寸以上不少于 300ms。

### 5.2 转场选择

- 上下层级：Compact 优先左右位移；Expanded 优先淡入淡出或容器内转场。
- 新建任务：触发点在底部时可从下方进入；宽屏按触发位置选择，不固定从屏幕边缘飞入。
- 搜索：搜索框存在时使用共享元素；只有搜索图标时使用淡入淡出。
- 卡片到详情：优先共享容器或共享元素，维持标题、图片或图表对象连续。
- 列表刷新：只对新增、删除或重新排序的对象做局部动画，不整页闪烁。
- 手势：按下立即反馈；离手继承速度；越界提供阻尼；中途取消时平滑回到原状态。

默认可使用标准曲线 `cubic-bezier(0.40, 0.00, 0.20, 1.00)`；入场使用减速、退场使用加速，跟手和自然回弹优先系统弹簧。不要在同一转场中混用多套无关曲线。

### 5.3 可访问性与性能

- 系统启用“减弱动态效果”时，移除视差、缩放、长距离位移和非必要粒子，保留 100–150ms 淡入淡出与状态反馈。
- 动画不得阻塞点击、返回或数据提交；业务结果以状态为准，不能依赖动画结束才写入。
- 不可见、进入后台或灭屏时立即停止动画；循环动画必须有明确停止条件。
- 优先变换和透明度，避免动画过程中频繁触发布局与大面积重绘。
- 沉浸光感、模糊、阴影和粒子均需低算力降级；保持信息层级，不强求视觉效果完全相同。

## 6. 组件状态契约

所有交互组件必须覆盖：`default / hover / pressed / focused / selected / disabled / loading / error` 中适用的状态。

- `hover` 只提示可操作性，不能承载必须信息。
- `focused` 与 `selected` 是不同状态；键盘焦点轮廓不得被品牌填充吞掉。
- `disabled` 除降低视觉权重外，还要阻止事件并解释无法操作的原因；长期不可用的功能应考虑隐藏。
- `loading` 保持控件原有尺寸，防止页面跳动；提交中的主按钮避免重复触发。
- `error` 给出发生了什么和怎么恢复，不只显示红框。
- 危险操作使用警示色、明确动词与后果；不可逆操作需要确认或可撤销机制。

## 7. 多端验收清单

### 7.1 视觉与排版

- [ ] 页面仅使用语义 Token，无散落色值、字号、间距和圆角。
- [ ] Light / Dark 均无文字、图标和图表对比度问题。
- [ ] 正文对比度 ≥4.5:1；图标和标题 ≥3:1。
- [ ] 系统最大字体下，关键内容不截断、重叠或不可操作。
- [ ] 金额和数据列对齐，涨跌不只靠红绿判断。

### 7.2 布局

- [ ] 在 599/600/839/840vp 临界宽度前后测试，无跳动、重叠或状态丢失。
- [ ] 横竖屏、分屏、自由窗口、键盘弹起和安全区均可用。
- [ ] 图片不变形；大屏没有简单拉伸；阅读内容有最大宽度。
- [ ] 折叠状态变化后保留当前任务、滚动位置与未提交输入。

### 7.3 交互与动效

- [ ] 所有非一级全屏页面有返回/关闭/取消，系统返回始终有效。
- [ ] 触屏热区 ≥40×40vp，主要操作推荐 ≥48×48vp。
- [ ] 鼠标、键盘、触控板和触屏完成同一任务时结果一致。
- [ ] 页面转场无单帧硬切，时长满足对应屏幕等级下限。
- [ ] 减弱动效、低算力、后台和灭屏场景有正确降级或停止行为。

### 7.4 内容与全球化

- [ ] 中文、英文长文案和 RTL 至少各验证一轮。
- [ ] 日期、时间、币种、千分位和涨跌规则来自 locale/market，不在 UI 中硬编码。
- [ ] 权限在使用场景内申请，说明具体用途；拒绝权限后可继续使用非相关功能。

## 8. 落地优先级

1. **P0：建立 Token 层**——颜色、字体、间距、圆角、动效时长统一入口，清理页面散值。
2. **P0：统一三断点外壳**——导航、页面边距、内容最大宽度、列表—详情规则先稳定。
3. **P0：补齐硬性验收**——对比度、热区、返回、安全区、大字体和窗口缩放。
4. **P1：统一组件状态**——按钮、输入、菜单、列表、弹窗、表格、图表状态齐全。
5. **P1：建立动效 Token 与减弱动效**——先做反馈与转场，再做品牌动效。
6. **P2：接入沉浸光感**——在支持范围内渐进启用，完成低版本和低算力降级后再扩面。
7. **P2：扩展端专项规范**——穿戴、智慧屏、座舱按真实业务需求单独立项。

## A3. 设计理念

口号：**One Harmonious Universe**

- **One**：人因优先；字清晰、图标准、色协调、动效流畅；层次清楚；操作符合本能。
- **Harmonious**：数字界面映射物理世界的光影与材质。
- **Universe**：多设备自适应；交互尽量一致，设备差异要单独设计；同时做数字健康、全球化、无障碍。

## A6. 圆角

原则：同层统一；层级越高圆角越大（弹出层 > 小控件）。

常用：

- 4vp 标签 / 角标
- 8vp 图片 / 图标
- 16vp 卡片 / 内容容器
- 20vp 按钮 / 菜单
- 32vp 半模态 / 弹出框

Token：`corner_radius_none=0`，`level1=2` 起每档 +2vp，到 `level13=26`；`level16=32`，`level18=36`。

电脑按钮刻意用更小圆角。

## A7. 间隔

只用 4vp / 8vp 倍数，禁止随意数。层级高、独立性高 → 间距大。同类组件间距一致。内容不贴边。

### 屏幕边距 margin（左右 / 顶 / 底）

| | 手机 | 折叠 | 平板 | 智慧屏 | 穿戴 | PC | 座舱 |
|---|---|---|---|---|---|---|---|
| 左右 | 16 | 24 | 32 | 48 | 26 | 40 | 48 |
| 顶 | 36 | 36 | 36 | 27 | 20 | — | — |
| 底 | 28 | 28 | 28 | 27 | 20 | — | — |

泛手机常用：卡片 12vp；有边界控件 16vp；无边界 8vp；主次文本上下 2vp、左右 8vp。

Padding token：`Padding_level0=0` 起偶数档到 72（中间缺 28、48 等若干档，以官网全量表为准）。

## A8. 布局

单位：

- **vp**：虚拟像素，跨密度视觉大小一致
- **fp**：默认 1fp = 1vp；开大字体后 `1fp = 1vp * scale`
- 网格 **8vp**（更小图标可对齐 **4vp**）

原则：布局完整（折叠/旋转不截断变形）；不用死 px，用弹性 + 断点；**移动优先**，先保最小屏完整。

栅格列数随窗口宽：

- `< 600vp` → 4 列
- `600–839vp` → 8 列
- `≥ 840vp` → 12 列
内容最大宽 **2220vp**，再宽左右留白。

栅格示例：4 列 margin 16 / gutter 8 或 16；8 列 24/12；12 列 32/16 或 32/20。Gutter 不大于 Margin。

安全区：避让状态栏、导航条、挖孔、折叠转轴；多窗时内容居中不要贴边。

### 响应式架构

- `≥ 600vp`：分栏，默认 4:6，可 5:5 / 6:4
- `≥ 840vp`：底 Tab 变侧边 Tab（选项不变）或侧边导航栏（必须扩展层级/入口，不能只挪位置）

八种布局手法：拉伸、缩放、延伸/隐藏、折行、缩进、挪移、重复、分栏。不要整页等比放大超过屏 50%；图片放大超 150% 改用重复布局。

## A9. 图标与 Symbol

应用图标：前景+背景双层 PNG，**1024×1024** 正方形，**不要自己做圆角/透明底**（系统遮罩）。光从上往下，上浅下深，避免斜向渐变。主图形居中，别贴四角。

Symbol：当字体用。标准 **24×24vp**，图形落在 22×22；描边 1.5vp，圆头，外圆角 3 / 内 1.5，断口 1.3vp。渲染：单色 / 分层透明度 / 多色。动效：出现、消失、弹跳、缩放、替换、快速替换、脉冲、可变颜色、禁用。`SymbolGlyph` 独立图标；`SymbolSpan` 图文混排。

## A10. 沉浸光感

界面当光学介质，不是实色块。用户三档：强 / **均衡（默认）** / 弱。开发用 5 档材质，系统映射用户档位：

- 顶部悬浮：`ULTRA_THIN` + 渐变模糊
- 底部悬浮：`THIN` + 渐变色蒙层
- 任意位置弹出：`THICK`
- 半模态 / 大弹窗：`ULTRA_THICK`

有色按钮不要直接 `BackgroundColor` 盖掉光感，用材质色接口。

从 API 26 起，ArkUI 可按设备算力、系统深浅模式和用户设置自适应沉浸光感。开启会消耗较多 GPU 资源，且只有标题栏、底部页签及官方列出的弹窗、菜单、选择类组件等范围生效；不支持或低算力环境必须准备语义色背景降级。

标题栏：渐变模糊比标题底边高出 **32vp**；默认 1px 分割线；跟手可直接显隐或过渡变色。单行标题高 **56vp**，强调型 **112vp**。

## A11. 动效

引力体系：即视感、秩序感、控制感。原则：自然流畅、简洁高效、快速响应、运动一致、隐藏等待、凸显品牌。

时长：短距离约 150ms，局部约 200–250ms，长距离 / 全屏通常不超过 350ms。简单变色约 100ms，复杂旋转约 300ms，开关类小范围约 150ms。全屏转场还要满足 UX 标准的设备尺寸下限：200 / 250 / 300ms。

曲线：在视线内用标准贝塞尔（例 `cubic-bezier(0.40,0.00,0.20,1.00)`）；入场减速；退场加速。跟手 / 滚动用弹簧（Stiffness / Damping / Mass / Velocity）。交互动效对齐屏幕刷新率（常 60fps）。

转场先定层级（同层 / 上下级 / 跨应用），再拆进场、出场、持续、静止元素。推荐一镜到底：共享元素、共享容器、共享动势。转场约占系统动效 60%+。

手势动效按下即反馈（按下接触约 100–130ms，不要等抬起才动）。滑动分跟手 / 离手瞬间继承手速 / 离手后。要有过界阻尼（显控比）。

## A12. 控件摘录

**按钮**：强调 > 填充 > 文字。不可逆操作用警示红。普通/小两档尺寸。手机横屏按钮最大 **448vp**；双按钮间距 12vp；半模态左右各留 16vp。大屏按钮不再跟着屏幕无限变宽。穿戴有贴边弧形按钮；不可用文本透明度 40%。

**标题栏**：一级页左侧不要返回（Mini 除外需隐藏）；非一级必须返回或关闭。右侧操作与当前页相关，多了收进「更多」。正文标题要短、加粗、对比够。

**列表**：同组样式一致；一级/二级/三级字色分层。横滑操作不超过列表一半宽、最多 3–4 项。手机效率型行高常见 48–96vp；内容型 64–120vp。右侧与中间内容间隔 12vp。头像 40/48/56；系统图标 16 或 24。

## A13. 人机交互

核心：按当前输入方式响应，体验一致。长按不要承担常用功能（发现性差）。车机不要长按 / 拖拽 / 指关节。

触屏基础：点击、长按、拖拽、滑动、双击、捏合、旋转、指关节敲击（仅手机/平板）。点击允许滑出热区取消；「按下即触发」不可反悔，只用于易撤销操作。

列表：左滑删除（同应用删除图标要统一）；右滑最多一个次要操作。半模态滑到内容底不要立刻关，再向下滑才关。

系统手势不要占用：底边上滑回桌面、边缘内滑返回、三指（平板/电脑）。不要二次返回挽留。游戏可 Toast「再滑一次退出」。

交互事件归一（同一接口映射多设备）：

| 意图 | 触屏 | 鼠标 | 触控板 |
|---|---|---|---|
| 点击 | 单击 | 左键 | 轻点 |
| 菜单 | 长按 | 右键 | 双指点 |
| 拖拽 | 长按移动 | 左键拖（不等待） | 按压移动 |
| 滚动 | 单指滑 | 滚轮，默认 64vp/格 | 双指滑 + 惯量 |
| 缩放 | 捏合 | Ctrl+滚轮 | 双指捏合 |

## A14. 文案、全球化、隐私

文案像「知识渊博的朋友」：您/您的；先说用户要的；短句；少失败/错误/双重否定。无害删除用「是否删除…？」；有害用「删除后…确定删除？」。无害确认用「是否」；有害用「确定」。异常 = 描述 + 解决办法。

全球化：图文分层；忌色/忌符号/忌手势；RTL 要镜像有方向的图标和转场。英文字符 ≤10 预留 100% 空位，10–20 预留 50%，>20 预留 30%（理想约 2 倍）。默认语言英文。日期数字走 ISO/CLDR/UTC。

隐私：最小必要、场景内申请。位置/相机/麦克风/图库/通讯录是高敏感。能用按钮式/选择器临时授权就不要弹框。权限说明写用途不是写「获取摄像头」。禁止后不许闪退、不许连环弹窗。

## A15. 上架级 UX 硬标准（通用应用）

必须项摘要：

- 除一级页外，全屏要有返回/关闭/取消；系统返回手势全程可用
- 布局不截断变形；挖孔不要挡住标题栏、Tab、搜索、输入、悬浮按钮
- 不要和系统边缘/指关节/三指手势冲突
- 长按识别 400–650ms（目标 500ms）；双击间隔 70–400ms
- 触屏热区 ≥ **40×40vp**（推荐 48）；穿戴推荐 46、必须 40
- 主滑动区高度 ≥ 屏高 20%（手机/折叠）
- 对比度：图标/标题 ≥ 3:1，正文 ≥ 4.5:1
- 字号下限：手机 8vp（推荐 ≥12）；电脑 10vp（推荐 ≥14）

## A16. 对照「照抄文档站」时的映射

文档站是 **PC 文档壳**，不是 HarmonyOS 应用壳，但用了同一套蓝和灰：

- 品牌蓝 `#0A59F7` = `brand`
- 顶栏灰 `#EBEDEF` ≈ `background_secondary` 附近
- 选中胶囊 = 中性黑高亮（`comp_background_neutral` 思路），不是蓝胶囊
- 左树选中才用品牌蓝满铺
- 正文柱 920px、左树 338px：适合 ≥840vp / 12 列文档场景
- AI Hub 现有「左侧全局导航」更接近 HarmonyOS **侧边导航栏**（≥840vp 且入口有扩展），不要和「侧边 Tab」（选项与底栏完全相同）搞混
