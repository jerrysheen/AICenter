# 日报 Skill 候选 v3.1：按分类浓缩小时模块

只读取给定小时模块，不重新读取信息稿、原文或旧分析。按规范的阅读分类合并跨小时内容：相同主体集中，重复只说一次，新进展或更正保留最新状态及必要的先前背景。不要将采集/发布时间当作实际事件时间。

每个日报模块是一段比对应小时正文合计更紧凑的内容。每件事留下最短而清楚的表达，删除教程步骤、重复背景、例子、宣传修饰和次要数字；不要逐小时复述、把全部句子串成一段，或靠不通顺的缩写假装压缩。不要生成影响、机会、建议、评分或共同趋势。

重要信息指本文主要事情和改变理解的条件，不等于数字最多的句子。作者观点仍是观点，计划不变成完成，数量描述的对象不变；无需保留的数字连同细节一起省略。不能把“设计/天”变成“订单/天”，不能把供货方与下单方倒置。存在不同说法时简短并列，不额外核验或裁判。

同类优先少量模块，null不能证明相关；不同且无法合理归为一类的内容允许分开。一个小时模块不能拆给多个日报父模块；若下层混杂，保持可理解并列并由离线验收定位分类问题，不为拆散而复制下层。

直接输入均须各出现一次，不能遗漏或新增ID。不为了减模块数删掉独立主旨，不为凑字数补文。单个已足够紧凑的小时模块允许原样复用。

标题与首句共同保留辨认内容所需的核心对象（人、机构、产品或方法）及动作；删参数、步骤、修饰语时不得删掉这些对象。标题写“具体对象＋发生什么”，不要写“重在流程”“配套方法”等抽象道理。教程保留使用的产品及关键做法，例如编辑示意“Claude动态视频：预览纠错后封装为Skill”；此例只说明表达标准，不得作为输入新闻生成。

响应遵守宿主注入的统一协议。
有效tagId使用宿主目录；ref和覆盖篇数由代码生成。每模块一个ref，先展开小时模块，再到信息稿；不生成逐句证据、原文链接、多对多关系或新内容节点。
