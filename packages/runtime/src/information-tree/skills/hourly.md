# 小时 Skill 候选 v3.1：归类、合并、再压缩

只处理给定的信息层短文，不读原文、不联网、不分析影响。按已规范的阅读分类组织少量模块；同一主体相邻，重复说法只表达一次，不同事情简短并列。目标是让人快速知道有哪些事情，不是把短文拼成长文。

每个模块text为一个短段落；各件事通常用一句短句或分号连接，先删背景和重复主语，再删实施细节、例子和次要数字。保留能辨认事情的主体、核心变化及必要的“计划、据称、作者建议”等状态。不得将几个输入的句子逐句换词后照搬。不要写导语、结语、价值分析或泛化趋势。

单个输入也是浓缩任务，长教程只留“什么方法、解决什么问题/必要条件”；已经简短准确的内容可复用，不强行压出不通顺的缩写。模块总字数是柔性阅读预算，不是删掉独立事情的依据。

null是未分类状态，不是“内容相关”。不要仅因为都为null把讣告、维修店和数据中心拼在一起；用少量可辨认的主题模块收纳，无法合理合并时允许保持分开。分类标签由宿主规范，无法在本批修正的分类冲突不能借改写事实掩盖。

每个直接输入ID在本期输出中恰好归属一个模块；不拆一个输入为多节点，不淘汰低热度信息，不输出未采用尾巴。输出模块数应服从内容组织，不为机械减数把不相关内容强并。

输入可能已经是多个事项的合并稿。此时整个输入仍是不可拆分的引用单元：即使包含体育、司法、市场等不同事项，也必须把它们保留在同一个输出模块，不能为按主题重分类而重复使用该ID。可让该输入单独形成综合模块，并在短段落内并列事项。先为每个输入选定唯一归属，再压缩正文；最终所有inputIds的并集必须等于完整输入ID集合，任意两个模块的inputIds不得重叠。

数字可省略，但保留时不得改变指标对象、单位、期间；例如“设计/天”不能缩成“日单”。不同说法可简短并列，不自动裁定真伪，不从先后发生推出因果。

必须保留会改变事实确定性或数值范围的词：“至多/最高/约/至少/预计/目标/尚未/据报道/传闻/作者认为”等不能因压缩变成确定结论。例如“速度至多提升10倍”不能写成“提升10倍”；“传闻产品周五发布”不能写成“产品周五发布”。投资额、融资额和估值不得混同；预测、计划、建议不得改成已发生事实。概括多个来源时分别保留必要的归因和状态。

标题与首句共同保留辨认内容所需的核心对象（人、机构、产品或方法）及动作；删参数、步骤、修饰语时不得删掉这些对象。标题写“具体对象＋发生什么”，不要写“重在流程”“配套方法”等抽象道理。教程保留使用的产品及关键做法，例如编辑示意“Claude动态视频：预览纠错后封装为Skill”；此例只说明表达标准，不得作为输入新闻生成。

响应遵守宿主注入的统一协议。
有效分类使用宿主提供的ID，空分类使用JSON null。ref、篇数和版本由程序保存；一个模块仅一个ref，不输出逐句引用、URL、证据、评分或额外层。

示意：关于设计工具的一篇长稿可压为“作者分享动态设计工作流：固化规则、渲染前评分修正，再封装为可复用Skill。”
提交前静默核对主要事项、归属ID、数字对象和计划状态；不返回检查过程。
